# 能力页方案：按档位 + 按群管理「能调什么」

> 状态：设计稿，未实现。2026-11-05。
> 目标：在 dsh-roost 侧栏新增一页，管理每个权限档位、每个群可以调用哪些 **DSH 工具**与 **skill**。

---

## 一、先划清事实边界（这一节决定整个方案）

2026-11-05 实测真实 QQ 会话的工具清单，共 34 个，来源如下：

| 来源 | 例子 | 怎么进来的 |
|---|---|---|
| preset 声明 | `edit` `read` `write` `pwsh` | `cordis.patch.yml` 里 `tool-fs` / `tool-pwsh` |
| 宿主插件 | `gh_repo` `ops_bash` `search_context` `acp_*` | profile 的 bundles，**自动继承**，不进 preset |
| MCP | `mcp__graphflow__gf_read` … | 宿主层 mcp-client，同样自动继承 |
| dsh-roost 自己 | `memory_search` `memory_note` | 我们 `agent.ctx.tools.register` |

三条由此得出的硬结论：

1. **工具池不是我们控制的**。宿主装什么，agent 就有什么。所以「管理」只能做**减法**（每轮 `tools.restrict` 收走），不能做加法——**但有一组钉住项不许减**（见下），所以准确说法是「可以减，例外硬编码」。
2. **减法是逐轮的**。`restrictTurnTools()` 每轮重算一次，所以策略改完**立即生效、不用重启**——这是本方案能成立的前提。
3. **skill 是例外**：它必须由 preset 静态挂 `skill-filesystem` + `tool-skill`，改一次要重启，且目录是全局的，天生做不到「按群」。要么接受这个限制，要么自己接管（见第八节）。

---

## 二、目标与非目标

**目标**

- 一个页面看清「这台机器上的机器人，此刻手里有哪些工具、分别给了谁」。
- 按**档位**（主人 / 管理员 / 成员 / 身份不明）配置允许集合。
- 按**群**叠加覆盖，不改默认策略。
- skill 同样可按档位、按群开关。
- 改完有「试算」，能立刻看到某一群、某一身份下一轮实际会看到什么。

**非目标**

- 不做沙箱。这层只管「AI 这一轮能调哪些工具」，插件代码仍以你的账户权限运行（README 已有同样的声明）。
- 不做插件安装/卸载。那是 DSH 插件市场的事，这里只做「配额」。
- 不做"给某个群单独一套人格"——人格已有独立页与 `roost-social` preset。

## 三、三层模型

```
① 池（Pool）       tools.schemas() 的真实返回          —— 只读，每轮取一次
        ↓
② 策略（Policy）   档位基线 → 群覆盖 → 人格求交 → 钉住项  —— 纯函数，可单测
        ↓
③ 执行（Enforce）  restrictTurnTools({ deny: pool − allow })  —— 每轮
```

### ② 的解析顺序（顺序即语义，不能乱）

1. `pool` = 本轮 `tools.schemas()` 的全部工具名。
2. `bucket` = `bucketOf(payload)`，落 `owner / admin / member / unknown`。
3. `base` = `capabilities.defaults[bucket].allow`；没配过就回退旧的 `permissions[bucket]`（`'all'` → `["*"]`，`'chat'` → 基础集）。
4. 群聊且有本群覆盖时：`base = (base ∪ allowAdd) − deny`。**覆盖是增量的**，不重写全量——否则换一次默认策略要改八个群。
5. 与 `persona.tools` **求交**：人格只能收窄，不能放宽（现有 `planPersonaTools` 的语义，保持）。
6. 加回**钉住项**（见下），无论策略怎么写都保留。
7. `deny = pool − base`，交给 `restrictTurnTools`。

### 钉住项（PINNED）

两类，硬编码在代码里（`src/capabilities.js` 的 `PINNED_KEEP` / `PINNED_DENY_SELF_SKILLS`），页面上灰显且不可关：

- **不许关**：`memory_search` `memory_note` `qq_send` `qq_close` `sticker_pick` `roost_skill`。关了机器人不是变安全，是变哑巴或失忆。
- **不许开**：`skill`——**只在 `skills.mode === 'self'` 时拦**，因为它会和我们自管的技能目录重复。切到 `native` 就放开。

> `qq_send_file` **不在**不许关里。关掉它还能发文字，只是不能发文件，那是合理配置；它在 `danger` 名单里，管的是"要不要二次确认"。

> 另一条不是洁癖：`tools.restrict` 一个名字写错就整批拒绝（0.10.10 踩过），所以 deny 集合必须由 `pool` 过滤而来，**永远不能出现 pool 里没有的名字**。`resolvePolicy()` 里第 ⑥ 步就是干这个的，并且有测试盯着。

## 四、数据模型

落 `~/.dsh/dsh-roost/capabilities.json`，与 `config.json` 分开：配置是"怎么跑"，这是"给谁用"，两者的修改频率和回滚诉求不同。

```jsonc
{
  "version": 1,
  "defaults": {
    "owner":   { "allow": ["*"] },
    "admin":   { "allow": ["memory_search", "memory_note", "qq_send"] },
    "member":  { "allow": ["memory_search", "qq_send"] },
    "unknown": { "allow": ["qq_send"] }
  },
  // 分组只影响展示与批量开关，解析时展开成工具名
  "groups": {
    "github":   { "match": ["gh_*", "pr_*", "issue_*", "review_*"] },
    "graphflow":{ "match": ["mcp__graphflow__*"] },
    "ops":      { "match": ["ops_*"] },
    "files":    { "match": ["edit", "read", "write", "read_image", "working_directory"] }
  },
  "chats": {
    "GROUP_OPENID_OR_BOUND_UIN": {
      "label": "测试群",
      "allowAdd": ["group:graphflow"],
      "deny": ["ops_bash"]
    }
  },
  "skills": {
    "mode": "self",            // self = dsh-roost 自管；native = 交给 DSH tool-skill
    "defaults": {
      "owner": ["*"],
      "admin": [],
      "member": [],
      "unknown": []
    },
    "chats": { "GROUP_OPENID": { "allowAdd": ["office-xlsx"] } }
  },
  "features": {
    // 每个功能：开关（按档位）+ 配额（谁 / 多久 / 几次 / 超了怎么办）
    "voice": {
      "allow": { "owner": true, "admin": false, "member": false, "unknown": false },
      "quota": { "per": "user", "window": "day", "max": 3, "onExceed": "reject" }
    },
    "sticker": {
      "allow": { "owner": true, "admin": true, "member": true, "unknown": false },
      "quota": { "per": "turn", "window": "message", "max": 1, "onExceed": "degrade" }
    },
    "proactiveGroup": {
      "allow": { "owner": true, "admin": false, "member": false, "unknown": false },
      "quota": { "per": "group", "window": "day", "max": 4, "onExceed": "queue" }
    },
    "memoryJournal": { "allow": { "owner": true, "admin": true, "member": true, "unknown": false } }
  },
  "danger": ["edit", "write", "ops_bash", "pwsh", "mcp__*__*_edit", "qq_send_file"]
}
```

要点：

- `allow: ["*"]` 是"全给"，写具体名字是白名单。**没写 = 不给**（fail-closed）。
- **`defaults` 是主配置，`chats` 只存例外**。页面默认只展开 `defaults`，`chats` 收在高级里；没有例外的群不产生任何记录。
- `features[x].quota` 缺省 = 不限（但功能仍受 `allow` 管）。`max` 是整数，**不写 cron，不写表达式**。
- `danger` 是个名单，只用于 UI 标红 + 二次确认，不参与解析。里面的 `*` **跨任意字符（含 `_`）**——否则 `mcp__*__*_exec` 连 `mcp__graphflow__gf_exec` 都匹配不上，等于一条永远不生效的规则。`exec` 比 `edit` 危险，两个都要在名单里。
- **`permissions` 与 `capabilities` 的关系**：首次运行生成 `capabilities.json` 时从 `permissions` 拷一次作为初始值，之后 `permissions` 只读、不再参与解析。避免"两个真相"——用户改了 `config.json` 里的 `permissions.owner`，界面却不跟着变。
- `chats` 的键优先用 **绑定的群号**（`identity.json` 里那套），拿不到才用 `group_openid`。换 AppID 后 openid 会变，用 openid 存的覆盖会失效——这一点要和「账号迁移」页联动提示。

## 五、面板：第 11 页「能力」

**信息架构：默认按档位，高级按群。** 这是全页唯一的排序原则——先管住「谁在说话」（覆盖 100% 的对话），再处理「哪个群要例外」（少数）。反过来的话，用户得先给每个群配一遍，配不完就放弃了。

放在「人格」之后（`order` 介于人格与记忆之间）。自上而下五层：

### A. 体检结论（一行，用结果说话）

```
群成员可以聊天、查资料，不能碰你的文件 · 覆盖 5 个群、约 130 人
⚠️ 有 3 个新能力还没分配
```

不写「已分配 21/34」这种配置语言。用户要的是**结论**，不是状态码。

### B. 四张身份卡（主视图）

| 卡 | 谁算这一档 | 默认角色 |
|---|---|---|
| 主人 | `owners` 里的 QQ 号、和你私聊的人 | 全权 |
| 管理员 | 群里的管理员 | 只聊天 |
| 群成员 | 其他所有人 | 只聊天 |
| 身份不明 | 认不出来的（缺字段、字段脏、框架改名） | 只聊天（**写死**） |

每张卡三行：

```
群成员                                     🟡
能：回话、记人、查资料
不能：碰你电脑上的文件、发文件、@ 人
影响：5 个群 · 约 130 人                    [换个角色 ▾]
```

- 角色就是四选一：**只聊天 / 能查能看 / 能干活 / 全权**。绝大多数人配完这一次就不用再进这页。
- 角色切换后，「能 / 不能」两行**立刻改写**——用户看的是这两行，不是开关。
- **影响面必须显示**。按档位配的人最怕的是「我不知道这影响多大」，而 `member` 档可能覆盖一百多号人。
- 「身份不明」单独标记为兜底档：写死不给工具，页面上不允许改（这是最后一道闸，不能被人手滑放开）。
- **`admin` 是真的会有人**：ai-chat 用 `level <= 1` 判管理员（`index.js:425`），所以框架里配了群管理等级就会有。但**不保证每个群都有**——卡片要能显示「0 人」而不是画一个永远填不满的档位。

### C. 高级：分群覆盖（默认折叠）

默认一刀切，但总有少数群要例外——公开群连聊天都别开，熟人小群可以放开。

折叠区顶部一句话交代清楚：

> 这里只配**例外**。没有列出来的群，一律走上面的默认。

- 群列表按最近活跃排序，显示群名 · 人数 · 最后说话时间（不是 openid）。
- 每行一个状态：`继承默认` / `已覆盖 3 项`。
- 点开是**增量编辑**：左边只读快照（默认给什么），右边两列「本群额外允许」「本群额外禁止」，中间是合并结果。不提供整份重写。
- 覆盖项数一直显示在卡片摘要上，避免"我以为它走默认，其实早被我改过"。

### D. 明细（再下一层，收在「自定义」里）

只有选完角色还想抠细节的人才进得来。工具按**危险度**分三组，不按来源分：

| 组 | 包含 | 说明 |
|---|---|---|
| 只看不改 | `read` `read_image` `search_context` `gh_search` `tool-web` | 看了也改不了 |
| 会改你的电脑 | `edit` `write` `pwsh` `ops_bash` `mcp__*__*_exec` | 🔴 打开要二次确认 |
| 会对外说话 | `qq_send` `qq_send_file` `sticker_pick` | 关了它就没法回话 |

技能并列在同一套开关里（用户理解上「技能」和「工具」本来就是一回事），只多一列「正文字数」。「按需注入」默认开：目录里只出现名字和一句 `whenToUse`，正文靠 `roost_skill(name)` 取——技能加到几十个也不会把提示词撑爆。

第三块是**功能**（第六节那张表）：记忆 / 表达 / 主动 / 上下文 / 运营。每个功能一行，左边开关，右边配额——配额用三个下拉拼一句话，**不出现任何输入框和表达式**：

```
语音条    [☑ 主人] [☐ 群成员]     每人 · 每天 · 3 次 · 超了回一句
表情包    [☑ 所有人]              每轮 · 1 张 · 超了不发
主动搭话  [☑ 仅私聊]              每群 · 每天 · 4 次 · 排队
```

钉住项（`memory_*` / `qq_send` 等）灰显加锁图标，鼠标悬停说明理由。

### E. 试算（选档位，可选群）

```
群成员 · 在「摸鱼群」
  它会：回话、查天气、记住你说过的话
  它不会：碰文件、跑命令、发文件
  这一轮注入约 1.2k token（比全权快 1–2 秒）
  被收走：gh_* 8 个 · mcp__graphflow__* 4 个 · ops_* 3 个
```

先给一句人话结论，明细折叠在下面。没有这块，用户点完开关只能去群里试——那是整页最容易劝退的一步。

## 六、功能开关与次数配额

工具管的是「DSH 给的能力」，这一节管「dsh-roost 自己的功能」。对用户来说两者是一回事——都是"它能干什么"，所以放在同一页、同一套开关里。

### 6.1 要能被开关的功能清单

| 类 | 功能 | 开关粒度 | 备注 |
|---|---|---|---|
| 记忆 | 跨群/本群事实、日记、知识图谱 | 各自独立 | 三层可以只留一层 |
| 记忆 | 关键词/向量检索 | 独立 | 向量要配 embedding 才有意义 |
| 记忆 | 凌晨巩固 | 独立 | 关了就不再升降级、不抽三元组 |
| 记忆 | 对话收尾 | 独立 | 只私聊，不发言 |
| 表达 | 分段发言（`qq_send` 多次调用） | 独立 | 关了退回"一整段被动切块" |
| 表达 | 发文件 | 独立 | |
| 表达 | @ 人 | 独立 | |
| 表达 | 表情包 | 独立 | |
| 表达 | 语音条（TTS） | 独立 | 依赖 provider 配好 |
| 主动 | 私聊排期 / 群聊主动 | 各自独立 | 群聊默认关 |
| 主动 | 三类机会（约定/想你/随性） | 各自独立 | |
| 上下文 | 压缩 | 独立 | **不建议关**，关了迟早爆 |
| 运营 | 本体自更新 / 人格库更新 | 各自独立 | |
| 运营 | 账号迁移 | 独立 | 只影响面板入口 |

### 6.2 配额：三件事必须说清

「限制次数」如果只给一个数字框，用户一定会填错。**谁、多久、几次**是三个独立维度，缺一个就不可解释：

| 维度 | 取值 |
|---|---|
| 谁 | 每个人 / 每个群 / 每个会话 / 全局 |
| 多久 | 每条消息 / 每分钟 / 每小时 / 每天 |
| 几次 | 整数；留空 = 不限 |

**「一条消息」和「一轮」必须分开定义**，否则计数一定错：`turn` = 一条用户消息触发的整轮（可能包含多次 `qq_send`），`message` = 单条发出的消息。表情包按 `turn` 计（每轮最多一张），语音条按 `message` 计（每轮最多三条）。

超了怎么办也要选，默认「拒绝并说明」：

- **拒绝**：回一句"今天语音条用完了"——**必须说话，不能静默**，否则用户以为坏了。
- **降级**：语音→文字、图片→不发。适合表情包这类非必要动作。
- **排队**：只对主动搭话有意义，攒到下一个窗口。

### 6.3 默认值（开箱即用，不需要用户想）

| 功能 | 默认配额 | 为什么 |
|---|---|---|
| 语音条 | 每人每天 3 条 | TTS 有成本，且群里连发语音很烦 |
| 发文件 | 每人每小时 2 个 | 防止被当成网盘 |
| 表情包 | 每轮 1 张 | 连发就是刷屏 |
| 主动搭话 | 每人每天 2 次、同群每天 4 次 | 这是最需要限制的，越界就是骚扰 |
| 记忆检索 | 每人每天 30 次 | embedding 按次计费 |
| 工具调用（非主人档） | 每群每小时 20 次 | 防刷 token |
| 全局 token | 每人每天 20k（可选，默认关） | 给"借给别人用"的场景 |

### 6.4 依赖：不能给一堆裸开关

功能之间有依赖，直接暴露二十个独立开关一定出事：

- 关掉「分段发言」→ `qq_send` 收走 → 模型只能输出纯文本 → 看起来像"它突然变笨了"。
- 关掉「表情包」但留着发图 → 模型会自己拼路径发图，绕过标签体系。
- 关掉「三层记忆」但留着 `memory_search` → 工具在，永远是空的。
- 语音条开着但 TTS 没配 → 每轮多一次失败调用。

所以页面要做**连带提示**，而不是让用户自己撞：

> 关掉「日记」会同时停用日记检索。`memory_search` 仍可用，但只查事实层。

规则：**被依赖项不能单独关**（灰显 + 说明），依赖它的项关掉时**自动列出会受影响的项**。

### 6.5 实现要点

- `src/quota.js`：滑动窗口计数，落 `quota.json`，按天分桶、过期分桶自动清理（不留垃圾）。
- 检查点只有两个：`channel.send` **内部**（`channel.js:180` 生成 `sp-`/`qs-` 键的地方）、tool `execute` 入口。**不要散落在业务逻辑里**，否则迟早漏一个。
- **顺序是硬约束**：幂等键在 `channel.send` 内部才生成，所以配额**不能**"在 send 之前按 key 检查"——那时还没有 key。正解是在 `channel.send` 里先生成 key、再查配额、`reuse` 命中直接跳过（重发不扣）。放外面必然出现"先扣后发"或"发完才发现超了"。
- 计数失败（文件坏了、并发写冲突）**按"本次放行"处理**并记 warn——因为限额是体验问题，不是安全问题，宁可多放一次也不能把正常对话堵死。

### 6.6 一句必须写进页面的话

> 次数限制只防刷屏和烧钱，**不是安全边界**。同一个人换个号、换个群就能绕过。真正的边界是上面的档位和工具开关。

## 七、列表会变：装完新插件 / 新技能之后

这一页管的是「当前这台机器上有什么」，而这件事一直在变。四种变化，两种节奏：

| 变化 | 什么时候可见 | 谁负责 |
|---|---|---|
| 装 / 卸 DSH 插件（bundle） | **重启 DSH 之后**工具才进 pool | pool 变 |
| 装 / 卸 MCP 服务器 | 同上（走 cordis patch 层） | pool 变 |
| 加 / 删 / 改 skill 文件 | **立即**，下次读盘就变 | 我们自己的扫描 |
| 升级 DSH 本体 | 工具可能改名或消失 | pool 变 |

### 7.1 行为层本来就是对的，过期的是界面

解析式是 `deny = pool − allow`：pool 变大，新工具自动落在 deny 里；pool 变小，旧名字自然消失。**运行时永远安全，不需要"刷新"这个动作。**

会过期的只有**可见性**——用户不知道它悄悄多了什么。所以这里要解决的不是策略失效，是"看不见"。

### 7.2 记一份 pool 快照

`capabilities.json` 增加：

```jsonc
"seen": {
  "tools":  { "gh_repo": 1762300000, "mcp__graphflow__gf_exec": 1762300000 },
  "skills": { "office-xlsx": "sha256:…" },
  "lastScan": 1762300000
}
```

- 面板打开时后端跑一次 `capabilities.scan`：取 pool、和 `seen` 求差。
- 新增 → 页签挂角标 + 顶部一行「新增 3 个能力，还没分配」，点进去直接定位到那三行。
- 消失 → 「3 个能力已失效」，标灰，给一个清理入口（见 7.4）。

来源归属不要猜得太死：`tools.schemas()` 只给名字和描述，不给包名。用前缀做**推测**（`mcp__graphflow__*` → Graphflow，`gh_*` → GitHub），并且明确标成「推测」——猜错比不猜更烦人。

### 7.3 新工具默认归谁

- `owner.allow = ["*"]` → 主人**自动拿到**新工具
- 其余档位是白名单 → 自动 deny

结论：**新能力默认只给主人**。安全，也符合直觉（"我装的插件，我自己先用"）。但页面上必须显式写出来，否则用户会以为"我没配过，那就谁都没有"。

留一个开关：`newTools: "owner-only"（默认）| "nobody"`。

> ⚠️ 这里原来有个逻辑洞：`*` 是无限集，`pool − allow` 时新工具必然落进 allow，所以 `nobody` 靠"排除 `*`"是表达不出来的。
> **解法在展开阶段，不在差集阶段**：`nobody` 模式下，`*` 只展开成 `seen.tools` 里已经见过的工具（`capabilities.js` 第 ② 步）。新工具从未见过 → 不在 allow 里 → 自动 deny。已由测试 `newTools=nobody 时 * 不含未见过的工具` 锁住。

### 7.4 失效的名字怎么清

**不自动删。** 三个理由：可能只是临时卸载、DSH 升级后可能改回来、误删要重配。

做法：标灰 + 「清理」按钮 + 清理前给出影响清单——"将删除 5 条引用，涉及 2 个群和 1 个人的覆盖配置"。用户点确认才动，动完进日志页。

### 7.5 刷新时机（不要到处扫）

| 时机 | 做什么 |
|---|---|
| 打开面板 | 扫一次 pool + skill 目录，更新 `seen` |
| 切档位卡 / 切群 | 用缓存，不重复扫（`schemas()` 有开销） |
| 每轮对话 | **不落盘、不比较**，只算 deny —— 热路径保持干净 |

### 7.6 顺手锁住一个老坑

`tools.restrict` 只要有一个名字不存在就**整批拒绝**（0.10.10 踩过，白名单从没生效）。现在解析是"`pool` 过滤之后再 deny"，所以装和卸都不会产生死名字。

这条要在 `resolvePolicy` 里加一句注释锁死：**任何情况下都不许直接拿配置里的数组去 restrict，必须先和 pool 求交。** 否则以后有人图省事绕过去，又是一整批静默失效。

## 八、技能：为什么要自己接管

DSH 的 `tool-skill` 有三个硬限制：必须在 preset 静态声明（改一次重启一次）、目录全局（做不到按群）、名字写错整个 preset 激活失败。

而我们的 `restrictTurnTools` 是逐轮的，所以「按群按档位给技能」这条路只有自管才走得通：

- `src/skills.js`：
  - 扫两个根：`<workspace>/.dsh/skills`（rank 100）、`~/.dsh/skills`（rank 400）。跳 `.system`。
  - 解析 frontmatter 的 `name` / `description` / `whenToUse`；坏文件跳过并记 warn，不让一个坏 skill 拖垮整页。
  - 按策略过滤后，拼一段极简目录注入 `systemPrompt.context`（和人格同一套注入路径）。
  - 注册 `roost_skill(name)` 工具：返回正文本体，超 8k 截断（与 DSH 的阈值对齐）。
- 与 DSH 原生并存时，把 `skill` 工具列进"不许开"，页面上标注「已由 dsh-roost 接管」。
- 改动 skill 文件即时生效（每次读盘，不缓存正文），这一点和人格「改完即生效」保持一致。

## 十、分期

| 期 | 内容 | 判据 |
|---|---|---|
| **P0** | 只读：工具清单 + 来源 + 试算 + **pool 快照与新增提示** | 不改任何行为，先让主人看见手里有什么；装个新插件重启后能自己跳出来 |
| **P1** | 档位矩阵可写，逐轮生效 | 群里普通人说话时，`gh_*` 确实调不出来 |
| **P2** | 分群增量覆盖 | 同一个群换身份，工具集不同；两个群互不影响 |
| **P3** | 功能开关（先接已有 config，不新增语义） | 面板上能关掉表情包/语音/主动，行为与改 `config.json` 等价 |
| **P4** | 配额（`quota.js`）：语音、发文件、主动、检索、工具调用 | 超限有话说、重试不重复扣、坏文件放行 |
| **P5** | 技能自管 + `roost_skill` | 群里能"用它会的技能"干活，且技能可按群关 |

P0 单独成期是有意的：**这一页最大的价值不是配置，是可见性**。现在 34 个工具是全自动继承来的，主人根本不知道自己给了机器人什么——先把这件事显示出来，本身就是一次安全改进。

P3 排得比配额前，因为**开关是对既有配置的搬运，配额是新增机制**。先把散在 `config.json` 六七个段落里的开关收进一个界面，用户第一天就能受益；配额要处理窗口、并发、重试去重，是另一类工程量。

## 十一、风险与红线

1. **这不是沙箱**。deny 的是"这一轮模型能调哪些工具"，插件代码仍跑在你的账户下。页面顶部要有一行常驻说明，不能只在 README 里写。
2. **deny 之后模型会"答应却做不到"**。要同步扩展 `rulesFor(bucket)` 的提示词，明确告诉它"你现在没有 X 权限，直接说没权限"，否则它会对群友说"好的我删了"。
3. **钉住项必须硬编码**。策略文件是用户可手改的 JSON，写坏了不能让机器人失忆或者不会说话。
4. **group_openid 会漂**。换 AppID 后群覆盖按 openid 存的那份就失效了，页面上要提示"请先绑定群号"。
5. **工具数会掉链子**。每次改完 `defaults` 都要用 `pool` 重新对齐，不能把上一轮的名字缓存下来直接用。
6. **别在页面里放"一键全开"**。对 owner 是全开没意义，对 member 全开等于把机器交出去。要放就放"全部拒绝"。
7. **配额不能当安全边界**。它只防刷屏和烧钱，换号换群就能绕。页面上必须写这句，否则用户会以为有配额就安全了。
8. **功能开关要防"关出哑巴"**。分段发言、记忆检索这类有下游依赖的，关之前要列影响；被依赖项灰显。

## 十二、测试要点

- `resolvePolicy` 纯函数：四个档位 × 有无群覆盖 × 人格收窄 × pool 缺项，表驱动。
- 钉住项：故意把 `qq_send` 从 allow 里删掉，断言它仍被保留。
- 危险工具：`danger` 里的工具对 `member` 打开时不报错（配置自由），但 UI 层要拦。
- 群覆盖增量：`allowAdd` 里有、`deny` 里也有的工具，**deny 优先**。
- **pool 变化**：模拟 pool 新增 3 个工具，断言它们全部落在 deny 里、且 `seen` 里被记为新增；模拟 pool 丢掉 2 个，断言不报错、旧名字标为失效而不是被静默删掉。
- **`seen` 缺失或损坏**（老用户首次升级）：不当作"全部是新的"，而是全量初始化一次并记 warn——否则一升级就弹"新增 34 个能力"。
- **skill 文件被删**：策略里那条引用标失效，注入的目录里不再出现，`roost_skill` 调用返回"没有这个技能"而不是抛异常。
- 面板：`expand()` 展开函数组件后断言字段级（现有前端测试的老毛病是只调子组件，「九页全过」是假的）。
- 空数据：pool 为空（DSH 版本差异）时页面不崩，状态条显示"报不出工具清单"。
