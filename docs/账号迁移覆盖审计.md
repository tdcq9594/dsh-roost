# 账号迁移覆盖审计（2026-11-13）

> 问题：换机器人（换 AppID）后 openid 全变，**现在是不是所有带 openid 的功能都能完好迁移？**
>
> 结论先说：**记忆本体（事实 / 日记 / 关系 / 授权）能迁，且迁得干净；配置里按 chatId 存的键和人物档案会静默失效或裂成两条**——这两类不在迁移链路上，也不会有任何报错提示。

---

## 一、迁移有两条路，覆盖范围不一样

| 路径 | 做什么 | 覆盖 |
|---|---|---|
| **① 绑定（只写身份表）** | `identity.json` 里给号码补一条 openid claim，存量数据一个字节不动 | 读取时按别名展开：旧键的内容**读得到**，但键还散着 |
| **② 一键改写（物理合并）** | 把旧 openid 键合并到号码键、删旧键，先整文件备份、失败自动回退 | 键结构真正变干净 |

两条路的共同前提是同一个函数：roost `src/identity.js:450 aliasesOf(kind, uin, current)` → `[号码, ...该号码名下 active 的 openid]`（不含当前 chatId）。
DSH 侧由 `src/host.js:1556 aliasesOf(chatId)` 提供，**只有接了这个参数的读取点才享受迁移**。

---

## 二、逐项清单

图例：✅ 迁移完好 ｜ ⚠️ 只迁一半 ｜ ❌ 不迁（换号后静默失效）

### 1. 记忆本体（✅ 全绿）

| 功能 | 位置 | 只绑定后 | 一键改写后 |
|---|---|---|---|
| 事实记忆 facts | `memory.json` `chats[chatId]` | ✅ `list / listRanked / listFull` 都带 `aliases` | ✅ 合并到号码键 |
| 记忆元数据 / 人设覆盖 / 授权 | `memory.json` `meta.chats` `personas` `authz` | ✅ `getPersonaOverride` / `hasAuthz` 带别名 | ✅ 合并（目标已有则不覆盖） |
| 日记 | `journal.sqlite` | ✅ `recent / recentTimeline / listChat / searchTerms / withVec / invalidated / clearChat / forget` 全带别名 | ✅ `rekey()` |
| 关系图（实体 / 边 / 经历 / 墓碑） | `graph.sqlite` | ✅ `nowEdges / closeEdge / isSuppressed / hasActive` 带别名 | ✅ `rekey()` |
| 「忘掉 / 清空」指令 | `apply-markers.js` | ✅ 带别名删，旧键一起清 | ✅ |
| 记忆巩固 / 压缩 | `consolidate.js` / `compact.js` | ✅ 带别名读，不会把旧键当陌生人 | ✅ |
| 扩展 `/v1` 记忆接口 | `ext-api-hooks.js` | ✅ 带别名 | ✅ |

### 2. 会话映射（⚠️）

| 功能 | 位置 | 只绑定后 | 一键改写后 |
|---|---|---|---|
| chatId → DSH 会话 | `sessions.json` | ⚠️ 新 openid = 新会话：**记忆接得上，对话上下文不接**（旧会话还留着，只是不再续） | ✅ 并键到号码键 |

### 3. 配置里按 chatId 存的键（❌ 全部静默失效）

这五处都是**字面量 `cfg.xxx[chatId]` 查表**，既不展开别名，一键改写也不碰 `config.json`。换号后一律退回全局默认，面板上看不出任何异常。

| 配置键 | 影响 | 代码 |
|---|---|---|
| `model.byChat[chatId]` | 单个会话的模型 / 思考强度例外失效 | 写 `host.js:5621`，读 `model-pick.js:47` |
| `persona.byChat[chatId]` | 按会话绑的人格失效 | `host.js:644`、`host.js:8167`、`personas.js:950` |
| `group.overrides[chatId]` | 按群覆写（插话概率等）失效 | `config.js:710` |
| `awake.groups[].chatId` | 群主动白名单失效 → 群里主动搭话**悄悄关掉** | `host.js:2611`、`host.js:2825` |
| `speakUp.chatId` | 主人私聊主动搭话的目标会话变空指针 → 主动搭话不再触发 | `speakup.js:69` |

> 注意 `awake.groups` 同时也是「权限 → 07 授权名单」里那张群白名单。换号后名单还在，但匹配不到任何群。

### 4. 人物档案（⚠️ 私聊能归户，群成员会裂）

`profiles.json` 用 `canonicalKey(who, aliases)` 归户（`profiles.js:49`）：

- 旧 openid 当 who → 归到号码（`canonicalKey(oldId, ['10001', oldId]) === '10001'`）✅
- **当前新 openid 当 who → 归不到号码**（`canonicalKey(newId, ['10001', oldId]) === newId`）❌

后果：换号后同一个人多出一条新档案，旧那条不再更新但仍在列表里；`profiles.recent()` 会把两条都列出来。
群里发言的成员更明显——群里传的 `aliases` 是**群**的别名表，成员的 openid 根本不在里面，从来不走归户。
另外一键改写的 `BACKUP_FILES`（`rewrite.js:60`）不含 `profiles.json`，不会 rekey。

### 5. 对话收尾（❌）

`closing.get/set(chatId)`（`closing.js:195/222`，调用点 `host.js:2608/3589`）按 chatId 存「上次收在哪、下次怎么接」，不带别名。换号后读不到，只是少一句提示，不丢记忆。

### 6. 统计与计数（✅ 影响可忽略）

`usage.json`（按 chatId 分行）、`quota` 计数、`awake.json` 状态计数、`delivery.json` 投递账本、`qq-tool-state` 挂载缓存、`recall-log.json`、`mood-history.json`、`events.json`（24h 过期）——换号后计数重开或分两行，总量不丢，功能不受影响。

### 7. 全局数据（✅ 不涉及 openid）

心情、自我叙述、人格库、表情包库、TTS、扩展记忆（按 extId）、权限档位、备份 —— 都是全局或按扩展存的，换机器人不受影响。

### 8. 群成员身份（设计内的人工步骤）

`people` 分区（群成员 QQ 号登记）解决的是「成员 openid ↔ QQ号」。不登记就只能按 openid 认人，换号后成员的档案、`quota` 计数会重新开始。这一块**没有自动化**：QQ 官方不给成员 QQ 号，只能本人提供。

## 三、缺口汇总（按严重度）

| # | 缺口 | 换号后的表现 | 位置 |
|---|---|---|---|
| P1 | 五个按 chatId 的配置键不迁移 | 按群覆写 / 群主动 / 单聊模型 / 人格绑定 / 主动搭话目标全部退回默认，**无任何提示** | 见 §3 |
| P1 | 人物档案不 rekey，当前 openid 不归户 | 同一人两条档案，旧条不再更新 | `profiles.js:49`、`rewrite.js:60` |
| P2 | `sessions.json` 只绑定不并键 | 记忆在、对话上下文断 | `sessions.json` |
| P3 | `closing` 不迁 | 少一句「上次收在哪」 | `closing.js:195` |
| — | 群成员身份靠手工登记 | 成员档案重开 | 账号迁移页「人」分区 |

## 四、换机器人的推荐顺序（按覆盖能力排）

1. **备份**（备份页导出 zip，或先配好加密云备份）。
2. 接新机器人，**数据目录不变**。
3. 让新机器人在目标群 / 私聊回一句话，新 openid 才会进会话表。
4. 账号迁移页 01：给每个旧键填号码 + 选类型 → 绑定（这一步就把记忆读通了）。
5. 想彻底合并：05「一键改写」→ 看计划 → 输「改写」执行（有备份，可回退）。
6. **手动补三处配置**（§3 那五个键）：设置页按群覆写、模型页的按会话例外、人格页的按会话绑定、主动搭话页的群白名单、语音/主动搭话页的主人会话 —— 换号后都要重新选一次。
7. 记忆页看事实有没有接上；人物页看档案是否多出一条（多出来就手工清掉旧的）。

## 五、怎么自查（不依赖面板）

```bash
# 旧键还散着多少（facts / journal / edges 三列）
node -e "import('./src/account.js').then(async m=>{})"   # 面板 /account/scan 走的是同一份 collect()

# 某个号码名下现在有哪些 openid
curl -s localhost:<端口>/api/identity?limit=200 | grep -o '"uin":"[0-9]*"' | sort -u
```

面板侧：账号迁移页 01「未对上」的条数 = 还没绑的旧键数量；绑定后该行消失，但**只有一键改写才会真的把键合并**。
