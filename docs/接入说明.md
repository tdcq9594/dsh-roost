# 接入说明：框架外接协议直连

> **2026-11-12 起改版**：本插件已**完全移除 ai-chat 中间层**。
> 旧版那份「`POST /inbound` + 回调 `/r/reply`」的宿主协议契约已废弃，
> 相关端点、一次性令牌、180 秒挂起窗口、插件市场安装与适配器配置全部删掉了。
> 本文只描述现在的链路。旧契约的历史分析留在 Git 历史里。

---

## 一、现在的链路

```
QQ ⇄ Roost 框架（QQ 官方接口） ⇄ 外接协议 roost-host/1 ⇄ dsh-roost ⇄ DSH 会话
```

- **收消息**：框架把**原生事件**通过 WS / SSE 推给本插件，字段不做 OneBot 翻译
  （`openid`、群号、身份档位、附件、`@` 原样给）。客户端在 `src/roost-host.js`，
  事件转 payload 在 `src/roost-payload.js`，接话判定在 `src/roost-decide.js`，
  连发合并在 `src/roost-merge.js`。
- **发消息**：一律走 `channels.active().send()`，即 `src/channel.js` 的直连通道，
  最终调协议 `msg.send` / `media.send`。框架侧的 `outbound` 负责限速、额度、
  被动窗口、审核识别和投递账本——**不再有绕过调度器的旁路**。
- **回话地址**：没有 HTTP 回调了。`postReply()` 只认 payload 里的
  `__channel.send` 函数（同进程注入），外部无法传入 URL，SSRF 面随之消失。
- **固定服务仍在**：`/v1` 控制面、`/capabilities`、`/tts`、`/health` 继续跑在
  `server.port`（默认 17321，被占自动顺延）。扩展投递 `/v1/message` 也是
  同进程构造 payload 后调 `onInbound`，不经过 `/inbound`（该端点已关闭）。

协议帧、方法表、scope 与鉴权见 Roost 仓库的 `docs/宿主协议v1.md`。

## 二、首次接入向导

新装和**老版本升级**都会强制走一遍四步向导，因为删掉 ai-chat 后老配置的
`channel.current='qq'` 已无对应实现，不重新接就是哑的。

1. 接入说明（展示旧/新链路对比）
2. 确认 Roost 装好并启动
3. 一键直连 —— 通过 Roost 面板 API 开协议、`token:'auto'` 生成密钥、读回真实端口
4. 自测完成 —— **后端真跑一次 `pairing.test()` 才写 `setup.wizardVersion`**

机制在 `src/setup-wizard.js`，配置是递增的 `WIZARD_VERSION`（不是布尔）：
以后再出破坏性迁移，+1 就能让所有人重走。「暂时跳过」只记
`wizardSkippedVersion`，不写完成，概览页会一直催，也能随时点「重新走接入向导」。

老配置的 `channel.current='qq'` 由 `migrateChannel()` 归一成 `roost`；
`createChannelRegistry()` 在只有一个实现时也对未知名字回退，双保险防止升级即全哑。

## 三、仍然有效的约定

| 项 | 说明 |
|---|---|
| 权限字段 | 事件里的 `sender.bucket/level/role` 决定这一轮能挂哪些本地工具；算不准时**不传**比错报成 member 安全，缺失一律按 `unknown`（只能聊天）处理 |
| 失败也要回话 | AI 报错、会话拉不起来、超时，每一种都要回一句人话；不回用户只会看到沉默 |
| 一轮结束还原 | 工具权限和「谁在说话」在本轮结束后还原，不串到下一句 |
| 接话策略 | 直连后框架会推**每条**群消息，靠 `roostHost.decide` 拦（ai / mention / window / engaged + 冷却 / 限频 / 静默时段），否则每句都触发一次模型调用 |

## 四、排查「群里 @ 了但没反应」

按顺序看，每一步都有可核对的判据：

1. **向导走完了吗** → 概览页有没有「重新走接入向导」按钮；没走完就先走完
2. **概览 → 直连状态** → `state=online` 且 `seq` 在推进才是真的收到了事件；
   `seq` 停着不动就是事件没进来，`state=error` 会带出具体原因
3. **Roost 那边开了吗** → 面板「外接」页：协议 enabled、依赖 `ws` 已装、
   token 已设置、端口与客户端配置一致
4. **测一下** → 接入页「测一下」或向导第 4 步，真打一次协议 `system.ping`
5. **固定服务在听吗** → `curl http://127.0.0.1:17321/health` 应回 `{"ok":true,...}`；
   `server.token` 配了但客户端没带，`/capabilities`、`/tts` 会 401
6. **AI 那边出错** → 概览「最近一轮」显示失败原因和耗时；再看「排障」页日志
7. **群里不接话但私聊正常** → 检查 `设置 → roostHost.decide` 的接话模式与冷却

端口被占用时会自动顺延（`lease.js`），以启动日志和面板为准，**不是固定 17321**。
