# 接入说明：宿主协议的两端

本插件实现的是 **ai-chat 插件定义的宿主协议**。
规范的源头在插件仓：[AI宿主插件方案 §五](https://github.com/tdcq9594/qq-bot-roost-plugins/blob/main/docs/AI宿主插件方案.md)。

这份文档只写**本插件这一侧**怎么实现，方便排查「为什么没回话」。

---

## 一、收到的请求

```
POST http://127.0.0.1:17321/inbound
X-Roost-Token: <配置里的共享密钥，没设就不需要>
```

```jsonc
{
  "id": "evt_01H...",
  "chat": { "kind": "group", "chatId": "B2C3...", "name": "测试群", "groupId": "B2C3..." },
  "sender": { "id": "A1B2...", "name": "小明" },
  "text": "看图",
  "rendered": "看图\n（语音，转成文字是：你好）",   // 有就用它，没有才自己拼
  "quoted": "",
  "attachments": [ { "type": "voice", "asrText": "你好" } ],
  "elements": [],
  "history": [],
  "reply": { "url": "http://127.0.0.1:8080/api/plugins/ai-chat/r/reply",
             "token": "一次性令牌", "expiresAt": 1761456300000 },
  "adapter": "dsh"
}
```

**本插件的响应**：立刻 `200 {ok:true}`，然后**异步**去跑 AI。
不会等 AI 想完再回——ai-chat 等的是 `/reply`，不是这个响应。

出错的情况：

| 状态码 | 什么时候 |
|---|---|
| 400 | 不是合法 JSON，或缺 `id` / `reply.url` |
| 401 | 配了共享密钥但请求头 `X-Roost-Token` 不对 |
| 413 | body 超过 1MB |

---

## 二、回话

```
POST {reply.url}
{ "id": "evt_01H...", "token": "一次性令牌", "text": "看到了，是只猫。", "done": true }
```

**两条硬约束**：

1. **必须在 ai-chat 的超时之前回**。它等 180 秒，本插件自己的上限是
   `chat.turnTimeoutSec`（默认 150 秒），超时会回一句「想太久了，先算了。」
2. **只往本机地址回**。`reply.url` 的主机名不是 `127.0.0.1` / `localhost` / `::1`
   就直接拒绝——防止 payload 被拿来当 SSRF 跳板。

---

## 三、失败也要回话

这是最容易踩的坑：AI 报错、会话拉不起来、超时——**每一种都要回一句人话**。

不回的话，用户看到的是「宿主没回话」（ai-chat 等到 180 秒超时），
比「这边出了点问题：xxx」难受得多。

| 情况 | 回什么 |
|---|---|
| 上一轮还没结束 | 「上一条还在想，稍等一下。」 |
| 超过 `turnTimeoutSec` | 「想太久了，先算了。」 |
| AI 这一轮没输出文字 | 「这边出了点问题：AI 这一轮没有输出文字」 |
| 其它 | 「这边出了点问题：<原因>」 |

---

## 四、排查顺序

「群里 @ 了但没反应」按这个顺序看：

1. **ai-chat 那边接了吗** → 插件面板开「调试日志」，日志里会写每条为什么没接
2. **端口对不对** → ai-chat 的「DSH 地址」是不是 `http://127.0.0.1:<本插件端口>`
3. **本插件在听吗** → `curl http://127.0.0.1:17321/health`，返回 `{"ok":true,...}`
4. **密钥对不上** → 401 会打在 DSH 日志里（「inbound 鉴权失败：密钥不对」）
5. **AI 那边出错** → 面板「状态」页的「最近一轮」会显示失败原因和耗时
