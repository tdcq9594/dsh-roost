# 接入说明：Roost 侧需要提供什么

本插件依赖 Roost 的三个接口。这份文档是**两边对齐用的契约**——
Roost 按这个实现，插件按这个调。

> 现状：这三个接口在 Roost v0.7.2 里**还没有**，是
> [`DSH-Aurabot适配方案-v2.md`](https://github.com/tdcq9594/qq-bot-roost/blob/master/docs/DSH-Aurabot适配方案-v2.md)
> 里的 P1。所以本插件目前是「装得上、连不上消息」。

---

## 鉴权

面板已有的那套，不新增：请求头 `X-Access-Key` 或查询串 `?key=`。
插件用 `?key=`，因为 SSE 的 `EventSource` 传不了自定义 header
（本项目手写 SSE 解析，其实能带头，但保持和浏览器端一致，省得以后换实现要改）。

未设置 `webui.accessKey` 且只监听 `127.0.0.1` 时不需要鉴权。

## ① `GET /api/stream` — 事件下行

现有的 SSE 通道加一路事件，不要新建端点（面板前端已经连着了）。

### `event: message`

每收到一条**消息类事件**就推一条。字段是 Roost 规范化后的 Message 的精简版：

```jsonc
{
  "botId": "main",              // 多机器人时用来分流
  "kind": "group",              // group | c2c | guild | dm
  "chatId": "group:B2C3...",    // 会话键，插件用它映射 DSH 会话
  "groupId": "B2C3...",
  "userId": "A1B2...",
  "userName": "小明",
  "content": "看图",            // 已去掉 @机器人 前缀
  "mentioned": true,
  "addressed": true,            // mentioned || isCommand || sticky
  "isCommand": false,
  "msgId": "ROBOT1.0_xxx",      // 被动回复用
  "msgIdx": "REFIDX_xxx==",     // 引用回复用（message_reference）
  "refMsgIdx": "TMP_xxx",       // 这条引用了谁
  "quoted": "被引用的原文",      // 有引用时给原文，没有就是空串
  "attachments": [              // 官方附件，原样给（含语音 ASR）
    { "type": "voice", "url": "...", "asrText": "你好", "wavUrl": "https://...wav" }
  ],
  "ark": null,                  // 卡片结构化：{ type, name, title, desc, url, fields }
  "elements": [],               // msg_elements：type 为 chatRecord / quote / ark / text
  "at": 1761456000000
}
```

**要点**

- `attachments` 里的 `asrText` / `wavUrl` **必须原样带上**——这是本插件相比
  OneBot 方案的核心优势，插件侧不打算自己跑 ASR。
- `elements` 里 `type: 'chatRecord'` 就是合并转发，`content` 是官方展开后的文本。
- 机器人自己发的消息**不要推**（否则会自己跟自己聊）。
- 推送要**脱敏**：不带 `raw`（里面有 `auth_token`），不带 AppSecret。

### 其它事件

`hello` / `log` / `status` 保持现状，插件会忽略。

## ② `POST /api/qq/call` — 能力上行

通用调用，一个端点覆盖官方全部接口。

**请求**

```jsonc
{
  "bot": "main",                    // 可选，多机器人时指定
  "method": "sendGroup",            // QQApi 上的方法名
  "args": { /* 原样透传给该方法 */ },
  "confirm": true                   // 危险操作必须带
}
```

**响应**

```jsonc
{ "ok": true,  "result": { /* 官方返回的原始 JSON */ } }
{ "ok": false, "error": "人话说明", "code": 40034100 }
```

**实现要点**

- `method` 必须在白名单里，白名单 = `src/endpoints.js` 里 `OFFICIAL_ENDPOINTS`
  的 `api` 字段去重后的集合（47 条 → 约 35 个方法名）。
  不在白名单直接 400，**不要把任意方法名透传给 `ctx.api`**。
- `args` 原样透传，**不在这一层做字段裁剪**。官方以后加字段不用改这里。
- 但有两个例外要处理：
  1. 带 `target` 的方法（`sendGroup`、`getGroupInfo` 等），第一个位置参数是
     target，调用方用 `args` 传不方便 → 约定 `args.__target` 取出后作为第一个参数。
  2. 危险方法（`removeMembers` / `operateGroupBlacklist` / `executeJoinStrategy` /
     `deletePanel`）必须 `confirm: true`，否则 403 并说明风险。
- 错误要翻译成人话：把官方错误码（如 `40034128` 被动回复超限）映射成可读文本，
  再把原始码放在 `code` 里。
- 记审计日志：谁、什么时候、调了什么、成没成。AI 调接口出问题时要能回溯。

## ③ `GET /api/qq/capabilities` — 能力清单

直接把 `OFFICIAL_ENDPOINTS` 吐出来，加一个 `risk` 字段：

```jsonc
[
  {
    "api": "sendGroup",
    "method": "POST",
    "path": "/v2/groups/{group_openid}/messages",
    "group": "消息·群",
    "risk": "write",          // read | write | danger
    "note": "被动 5 分钟 / 同一条最多 5 次"
  }
]
```

`risk` 建议按这个方法会不会造成不可逆影响来分：

| risk | 例子 |
|---|---|
| `read` | `getGroupInfo`、`getMe`、`listPanels` |
| `write` | `sendGroup`、`createPanel`、`setGlobalMenu` |
| `danger` | `removeMembers`、`operateGroupBlacklist`、`executeJoinStrategy`、`deletePanel` |

插件把这个清单喂给 AI 的 `qq_api_help` 工具，AI 才知道「官方还有什么能调」。

---

## 为什么不做成「每个接口一条 REST」

47 条路由要维护、要写测试、要文档；而且官方新增接口时两边都要改。
通用调用 + 白名单 + 能力清单，新增接口只在 Roost 的 `endpoints.js` 加一行，
插件侧零改动。

代价是少了 REST 的语义化（路径即资源）。但这里的调用方是 AI，
它看的是 `method` 和 `description`，不看 URL 长什么样。
