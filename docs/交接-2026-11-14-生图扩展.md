## 1. 为什么扩展不能自己发图（这条决定了整个设计）

MCP 的工具调用只带 `arguments`，**没有「当前是哪个会话」**。宿主给扩展的只有
`ROOST_API_URL` / `ROOST_EXT_ID` / `ROOST_LAUNCHER_DIR` / 配置 / 令牌，
`/v1/send` 却必须给 `target`（`ext-api-hooks.js:336`，缺了直接 400）。

所以改成：

```
模型 → image_gen(prompt) → 画 → 存 out/ → 返回绝对路径
                                        ↓
模型在回复里写 <<image-alone: 路径>>   → 出站动作层上传 → QQ
```

这条路是通的，而且不用改宿主：`outbound-actions.js` 的 `looksLikeSource()`
认 `[a-z]:[\\/]` 开头的 Windows 绝对路径，`<<image-alone:>>` 会走 `imageAlone` 动作。

顺带一个更好听的理由：画完不会往群里甩图，发不发、跟哪句话一起发由模型按语境决定。

**代价**：模型必须记得写标记。所以 `image_gen` 的返回文案里直接带可复制的
`<<image-alone: 完整路径>>`，`test/tools.mjs` 有一条断言钉住「没写就等于没发」。

## 2. 交付了什么

```
qq-bot-roost-plugins/plugins/imagegen/
├── plugin.json        15 个配置项（apiKey 是 secret）+ ui 段（table）
├── server.mjs         MCP stdio，4 件事；--list / --config / --call
├── lib/
│   ├── config.mjs     ROOST_EXT_CONFIG + ROOST_EXT_SECRET_APIKEY → 一份配置
│   ├── providers.mjs  OpenAI 兼容 / 自定义 / 备用链；纯函数 + 注入 fetch
│   ├── net.mjs        下载图片 + 按文件头判类型（不信 content-type）
│   ├── paint.mjs      画作库：存 / 列 / 编号定位（#1 最新）/ 删
│   ├── state.mjs      当日配额账本（先扣后画、失败退回、跨天归零）
│   ├── tools.mjs      4 个工具 + 参数硬校验 + 结果文案
│   └── ui-data.mjs    面板数据文件（tmp + rename，空列表不覆盖）
├── README.md          接法 / 面板 / 花钱 / 已知限制
└── test/              6 个离线用例 + smoke + live（手动）
```

工具：`image_gen` / `image_list` / `image_test`（真画一张验证）/ `image_delete`（要 `confirm`）。

几个当时做的判断，改之前先看：

| 决定 | 理由 |
|---|---|
| `batch` 没有，一次只画一张 | 一次画四张在群里是刷屏；要四张就调四次 |
| 配置只有 `array<string>`，备用链写成 `地址\|模型` | 宿主配置没有「对象数组」（`ext-config.js` 的 array.items 只能是标量） |
| `ref` 只认画作库编号 / 文件名 | 扩展不该因为模型随手一个字符串就去读本机任意文件 |
| 配额先扣后画 | 工具调用是并发进来的（server 的行循环不等 handle 结束），先查后扣会双花 |
| `response_format` / `image_size` 被 400 点名才去掉重发 | 被拒的请求没出图，重发不多花钱；其它 400 重试纯浪费 |
| 裸 base64 必须带图片魔数才认 | 有的服务把提示词回显在 JSON 里，光看字符集会把提示词当图 |

## 4. 下一个阻塞：模型侧没有「发图文卡片」的能力

B 站扩展 §3.1.5 第 2 步是「刷到好视频 → 发官方图文卡片（`msg_type=8`）」。
现在这条路两头都堵：

- **扩展发不了**：`/v1/send { card }` 要 target，扩展不知道会话（同 §1）；
- **模型发不了**：`qq-tools.js` / `markers.js` / `apply-markers.js` 里**没有任何卡片能力**
  —— `<<image:>>` `<<voice:>>` `<<button:>>` 都有，就 `card` 没有。

所以 B 站 card 之前，宿主得先补一个标记，比如：

```
<<card: 标题|描述|https://链接|https://图片地址>>
```

在 `outbound-actions.js` 里解析成 `{type:'card', value:{title,description,url,picUrl}}`，
复用 `channel.send({ card })` 和 `tuwenProblem()` 的校验（`ext-api-hooks.js:344` 那份）。
改完记得 `npm test`（基线 2339）+ `npm run ext-docs`。

**这是宿主改动，要单独一个提交，别和扩展混在一起。**

## 6. 纪律与坑（这次新增的）

- **索引必须用私钥重算**：`node scripts/build-index.mjs --key ../bot/keys/trust-private.pem`。
  私钥不在 `qq-bot-roost-plugins/keys/`（那个目录在 .gitignore 里），在 `douluo/bot/keys/`。
  只跑 `--check` 会发现不了「条目缺 author」这类手写字段，那次是我手补后 `sign-index` 重签的。
- **`out/` 不能进仓库**：`index.json` 的 sha256 是整个插件目录算的，多一张 png 索引就脏了。
  `live.mjs` 特意画到系统临时目录。
- **换行符**：插件仓 `* text=eol=lf`，写文件时别引入 CRLF（CI 有单独一步查）。
- 宿主那份 `test/smoke.mjs` 里我清空了 `ROOST_EXT_CONFIG`：跑测试的人自己机器上可能真配了接口，
  不清空「没配置」这条断言会被他自己的配置搞红。
