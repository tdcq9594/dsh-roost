## 2. 与原方案的三处偏差（动手前先看）

| 原方案写的是 | 实际做成了 | 为什么 |
|---|---|---|
| 「定时刷，醒着时间读 `GET /v1/state`」 | 按 `feedActiveHours` 自己判时段；`/v1/state` 只用来探宿主在线 | **`/v1/state` 里根本没有清醒时段**，只有 mood / bindings / lastBucket。宿主的判定在 `shouldFire()`，扩展看不到，硬猜会半夜照刷 |
| 「定时刷 + 主动推好视频」 | 只预热 `hot` 缓存和面板，**不往任何会话发消息** | 扩展拿不到 target；`/v1/proactive` 触发的是宿主自己的主动搭话，内容不受扩展控制，拿它推视频等于让她莫名其妙冒一句。和生图那半同一条边界 |
| 「截图 → `POST /v1/send { files }`」 | 截图存系统临时目录，返回绝对路径给模型写 `<<image-alone:>>` | 同上，而且**不能存扩展目录**：市场索引 sha256 按整个插件目录算，运行时多一张 jpg 会让 `build-index --check` 变脏 |

另外两条当时定的判断：

- **定时刷默认关**（`feedIntervalMin=0`，填 15 以上才启动）。0.2 的 README 写过一条真判断：
  MCP server 长驻，装了就一直打 B 站接口，412 迟早的事。开了还叠三道闸：
  活跃时段 / 宿主在线 / 撞过 412 的退避期。
- **刷到的只留内存**，不落 `feed.json`。`ui-data.json` 本来就在扩展目录里（0.2 既有行为），
  再添一个运行时 JSON 只会多一处污染索引的机会。

## 3. 卡片链路（宿主那半已经补好了）

```
模型 → card(link) → api.view() → 拼 <<card: 标题|描述|https://链接|https://封面>>
     → 模型原样写进回复 → markers.js 放行 → outbound-actions.js 校验
     → channel.send({ card }) → msg_type=8
```

`card.mjs` 在工具里就把长度 / https / 分隔符收拾好：宿主那边验不过只会记一条日志、
卡片静默不发，与其让模型莫名其妙少一张卡片，不如源头就挡住并说清原因。
**本地截图不能塞 `card.picUrl`**（官方只收 https），它走 `<<image-alone:>>`。
