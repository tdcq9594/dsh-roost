# 交接：扩展主动消息通道 + B 站 0.4（2026-11-14）

一句话：**0.3 那条「扩展发不了消息」的边界已经拆掉了**，但拆的方式不是给扩展
一把直发的钥匙，而是在宿主补了一条受治理的素材通道。

## 1. 做了什么

| 仓 | 提交 | 内容 |
|---|---|---|
| `dsh-roost` | `3f8c1eb` | `POST /v1/proactive/submit` + `src/ext-proactive.js`（队列/审批/门闸/结算）+ `speakup.fire()` 素材注入 + 面板第 03 节 + `extProactive` 配置段 |
| `qq-bot-roost-plugins` | `f5f5ed3` | `bili` 0.3.0 → **0.4.0**：8 → 10 工具、11 → 27 配置项，定时刷可主动推、写动作可选 |

链路：

```
扩展定时刷 → POST /v1/proactive/submit { cause,key,text,target,approve }
           → 宿主队列（去重 / TTL / 落 dataDir）
           → 门闸（免打扰、她要求安静、今日额度、群 group_push 授权）
           → speakup.fire(reason, { material, scene, target, hasGroupAuthz })
             把素材拼进 prompt，由模型决定说不说（<<skip>> 不占额度）
           → 真发出去才 settle（记账、清队列）
```

## 2. 关键设计判断

- **不新开 scope**：复用 `proactive:write`。它是敏感 scope，装扩展时主人已确认；
  新开一个只会让所有存量扩展重新走一遍授权。
- **扩展不能自报身份 / 目标**：`extId` 由令牌绑定；`target` 只认 `owner` 或
  `group:数字`。body 里塞 `extId` / `scene` 会被忽略并记 warn。
- **门闸复用 `shouldFire()` 的判定本身**，但传一份显式宽松的 cfg/state：
  `speakUp.canFire()` 绑的是「冷场搭话」那套随机排期 / 主人刚说过话就不说 /
  追问上限，套到「刷到一个东西想分享」上会让刚聊完天就永远推不出去。
  免打扰时段和静默必须守，所以不另抄一份时间逻辑。
- **群主动真算 `group_push` 授权**：`channel.send()` 的 `hasGroupAuthz` 默认
  `true`，传默认值等于跳过官方硬前置。没授权直接终局（`drop`），别每分钟撞。
- **只有真发出去才占额度**：skip / 发送失败都不算；失败留队重试 3 次。
- **审批**：面板 `extProactive.approval` 或单条 `approve:true` 时攒待批，主人私聊
  回「发 1」（`onInbound` 前置，只有真有待批才吞）或面板点「发」。只认
  「发 / 发送」开头，不抢 DSH 工具授权中继的「批准 / 同意 / 允许」。
- **主动轮次发不了图片 / 卡片标记**：`speakup.fire()` 里
  `raw.replace(/<<[^>]*>>/g, '')` 会把标记抹平。所以 B 站 0.4 的
  `autoShot` 只抽帧**存本地**、`pushCover` 只在素材里给 https 封面地址；
  `card` / `shot` 工具仍走「有人在场的那一轮」由模型写 `<<card:>>` /
  `<<image-alone:>>`。别试图在主动推送里塞标记。

## 3. B 站 0.4 的开关（全部默认关 / 写动作默认试运行）

`pushOwner` / `pushGroup` + `pushGroupTarget` / `pushApproval` / `pushCover` /
`pushMinPlay` / `pushDailyLimit` / `pushPerFeed` / `autoShot` /
`autoComment` + `commentTemplate` / `autoLike` / `autoDanmaku` + `danmakuTemplate` /
`writeDryRun`（**默认开**）/ `writeDailyLimit`。

- 新增工具 `push`（手动补推一次）、`push_state`（开关 / 额度 / 上一轮结果）。
  `push` 的 `readOnlyHint` 明确为 `false` —— 它会触发宿主主动发消息。
- **写动作没有注册成 MCP 工具**，只有定时刷内部会跑。0.2/0.3 的第一道安全边界
  「模型在工具表里找不到能对外说话的东西」仍然成立：群里任何人的一句话、
  或视频标题 / 评论里的注入文本，都没法让她去 B 站发评论。
- 写动作四道闸：`writeDryRun` 默认开、每日上限、Cookie 缺 `bili_jct` 当场拒、
  撞 `-101/-111/-352/-509/验证码` 当天暂停。
- 清单新增 `scopes: ['memory:write','state:read','proactive:write']`。
  **换机器 / 走市场安装时主人要重新确认一次敏感授权**，否则 403「缺少 scope」，
  `push_state` 会显示「通道不可用」。本机同步时已把 `proactive:write` 写进
  `api-clients.json` 的 `ext:bili` 记录（客户端存储每次 verify 都重读文件，
  不用轮换令牌、立即生效）。

## 4. 与 aurabot 的对应关系

| aurabot（内置模块） | 这里（MCP 扩展） |
|---|---|
| `api.every(60s) → tick()` + 清醒/额度闸 | `feedIntervalMin` + 活跃时段 / 宿主在线 / 412 退避 |
| `run()` 里 `think()` 把视频塞进 prompt | 扩展投素材 → 宿主 `speakUp.fire()` 拼进 prompt |
| `hub.sendText(private:ownerQQ, {proactive:true})` | `/v1/proactive/submit` → 宿主统一门闸与发送 |
| 群分享攒待批、回「发 1」 | `pushApproval` + 宿主队列审批（QQ 回复 / 面板按钮） |
| `hub.turnSendersAllOwner()` 判写操作 | 写动作不进工具表，只有定时刷内部按开关跑 |
| `dryRun` 默认 true / `pauseDay` / `maxCommentsPerDay` | `writeDryRun` / 风控暂停 / `writeDailyLimit` |

差别是**架构性的**：aurabot 是宿主进程内模块，拿得到 `hub` 和配置里的
`ownerQQ`/`groupId`；扩展是独立 stdio 进程，只能投素材，目标由宿主解析。

## 5. 怎么验证 / 怎么用

```bash
# 宿主
cd douluo/dsh-roost && npm test                 # 2366 全绿
npm run ext-docs:check                          # 通过

# 扩展
cd douluo/qq-bot-roost-plugins/plugins/bili
for t in test/*.mjs; do node "$t"; done         # live.mjs 跳过（真打 B 站）
node server.mjs --list                          # 10 个工具

# 面板
# 1) 扩展页确认 proactive:write 授权（本机已同步；换机器装仍要确认）
# 2) 「表达 → 刷 B 站 → 设置」：定时刷间隔填 ≥15、打开「私聊推给主人」
# 3) 宿主「主动说话」页第 03 节看队列 / 待批 / 今日用量
# 4) 或者让机器人调 push / push_state 手动试一次
```

宿主额度：`extProactive.maxPerDay` 默认 50；扩展还有 `pushDailyLimit` 默认 20。
两本账，和 `speakUp.maxPerDay` 也分开（但素材真发出去会记进 speakUp 的主动
开口账，即 aurabot 的「共享预算域」口径）。

## 7. 还没做

- 主动轮次里的**图片 / 卡片**：要发得让 `speakUp.fire()` 走 `outbound-actions`
  那套标记解析，或在素材通道里单独支持 `files` / `card`。现在是明确的限制。
- B 站写动作没有「模型自己组织评论措辞」：扩展没有模型调用能力，用的是模板
  （`{title}` / `{author}`）。要写得像人，得让宿主在消费素材时顺带产出一句评论稿，
  再由扩展提交——那会是另一个接口。
- 审批的 QQ 回复路径依赖 `onInbound` 里的宽松文本提取；如果实际 payload 的
  文本字段不在那几个常见位置，面板按钮仍然可用，但「发 1」会失效。真机验一次。
