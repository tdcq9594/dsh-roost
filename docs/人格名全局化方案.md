# 人格名全局化方案（v2）

> 目标：名字像 QQAgent 那样**全局生效**，人格文件只负责性格与说话方式。
> 默认名字：**大肥鱼**。
> 状态：N0 / N1 / N2 已实现（未发版）；`MIN_VERSION` 与 `package.json` 待发版时一起改到 0.11.0。

## 一、同类项目怎么做的

| 项目 | 名字放在哪 | 会不会进提示词 | 切换人设时名字变不变 |
|---|---|---|---|
| **QQ-agent** | `persona.botName`，**全局唯一** | 会（`{botName}` 占位符） | **不变**。分会话只覆盖 `roleText / participation / customRules / systemPromptOverride` 四个字段，名字永远取全局值 |
| **AstrBot** | `persona.persona_id`（同时当 name） | **不会**。`name` 只用于选择/显示，真正进提示词的是独立的 `system_prompt` | 不变（名字只是标识） |
| **SillyTavern** | 角色卡里的 `name` | 会 | 会——但它的模型是「一张卡 = 一个角色」，不适用于"一个机器人多种风格" |
| **我们（现状）** | 每份 `personas/*.md` 的 `name` | 会，而且注入**两次**（905、908） | 会——换人格等于换人 |

**QQ-agent 给出的理由值得抄**（原文）：分会话只覆盖说话风格，**机器人名字属于账号身份，永远取全局值——因为名字换了，@ 判定和历史消息里"我"的称呼都会对不上。**

结论：采用 **QQ-agent 的「名字=账号身份」+ AstrBot 的「名字不注入人格正文」**，两个原则合起来就是本方案。

## 二、目标 / 非目标

**目标**

- 名字只有一个来源，改一次全生效；
- 人格文件不再承担「我是谁」，只承担「我怎么说话」；
- 老用户升级后名字不变、文件不动、能回退；
- 默认名字是**大肥鱼**。

**非目标**

- 不做「每个群一个名字」——身份是机器人的，不是会话的（与 QQ-agent 一致）；
- 不做「一个人格一个名字」的兼容开关；
- 不改人格正文/示例/世界书的结构。

## 三、数据模型

### 3.1 全局名字

复用 `config.persona.name`（0.9.x 时代就是"人格名"，一直留着，语义升级）：

```jsonc
{
  "persona": {
    "name": "大肥鱼",              // ← 唯一权威
    "current": "default",
    "byChat": { "群id": "snarky" } // 只换风格，不换名字
  }
}
```

**默认值 `大肥鱼`**（`DEFAULTS.persona.name`）。取名字的回退链：

```
config.persona.name  →  当前人格的 label  →  当前人格的 id  →  "大肥鱼"
```

### 3.2 人格文件：`name` 废弃，改叫 `label`

```markdown
---
label: 吐槽          # 面板里区分风格用；不进提示词
tags: 短句, 吐槽
---
（正文，不写「我叫什么」）
```

- 新字段 `label`；**老字段 `name` 废弃**——只读一次、只作显示，之后从文件里清掉；
- 清理动作不是「删掉」而是「改名」：`name: 吐槽` → `label: 吐槽`，显示不丢；
- 两者都没有 → 面板显示 id；
- **提示词里不再出现人格文件的 `name`**（AstrBot 的做法）。

### 3.3 清除 `name` 字段的规则（关键）

清字段 = 改文件 = sha 变。市场人格一旦 sha 对不上，就会变成「你改过」，
从此收不到更新。所以**按文件来源分别处理**，不是无脑全删：

| 文件来源 | 判定 | 动作 |
|---|---|---|
| 用户自己写的（不在仓库清单、无 `.synced`） | 没有 sha 语义 | 备份后 `name` → `label` |
| 内置人格（包内有这份）且没改过 | `local === 包内 sha` | 改名 + 记 `.synced = {sha256: 包内 sha, localSha: 改名后}`，状态仍是「已是最新」 |
| 市场装的且没改过 | `local === rec.localSha` | 改名 + 更新 `rec.localSha` |
| **任何改过的**（用户手改过） | 对不上 | **不碰**。名字照样不生效，文件留给用户自己 |

最后一行是硬规矩：**迁移永远不覆盖用户的编辑**。用户改过的文件里就算留着
`name:`，它也不会被注入提示词——废弃字段的"废弃"靠读路径保证，不靠删文件。

### 3.4 提示词

```diff
- 你现在叫「{persona.name}」。
+ 你现在叫「{全局名字}」。

- 别忘了你是谁：{persona.name}。
+ 别忘了你是谁：{全局名字}。
```

正文原样拼在后面。**新增一条市场写作规范：正文不要自称**——正文里写死"你叫X"，换了全局名字就会打架。

### 3.5 内置人格的清理（发版时一次性）

| 文件 | 现状 | 改成 |
|---|---|---|
| `default.md` | `name: 小栖` | `label: 日常`（它本来是"话不多但有意思"的默认风格） |
| `fatfish.md` | `name: 大肥鱼`，正文第一句「你叫大肥鱼」 | `label: 吐槽`；删掉正文里的自称句 |
| 其余 6 份 | 各有 `name` | `label` 同值 |

这会改变 8 份文件的 sha → 发版时重跑 `build-persona-index.mjs`。用户那边会显示一次「有更新」，装完就正常了。

> 不这样做的话：全局名「大肥鱼」+ 默认人格 label「小栖」+ 正文「你叫大肥鱼」三者互相打架。

## 四、老用户迁移

### 4.1 判定看**磁盘上的原始配置**，不看合并后的默认值

`DEFAULTS.persona.name = '大肥鱼'` 是给新装的。老用户的 `config.json` 里没有这个键，
`loadConfig()` 合并默认值之后也会显示「大肥鱼」——不能拿合并结果判断"用户设过没有"。

所以迁移读**原始 `config.json`**：

| 原始配置 | 动作 |
|---|---|
| 有 `persona.name` 且非空 | **保留**（用户自己起的名，可能是 0.9.x 设的） |
| 没有这个键 / 为空 | 读一次当前人格的 `name`（如「小栖」）→ 写进配置 |
| 读不到（无人格 / 人格里也没 name） | 不写，走回退链 → 默认「大肥鱼」 |

### 4.2 顺序：先读名字，再清字段

1. 读当前人格的 `name` → 写 `config.persona.name`；
2. 按 §3.3 的矩阵把人格文件里的 `name` 改成 `label`（**跳过改过的**）；
3. 记一条日志：「名字已迁移为「小栖」；3 份人格的 name 已改名为 label，1 份因为改过没动」。

顺序不能反：先清字段再读名字，就只能读到空值。

### 4.3 幂等与回退

- 迁移只跑一次：配置里有值就不覆盖；文件里没有 `name` 就不动；
- 每个被改的文件先备份到 `.backup/<时间戳>/`（和删除/覆盖共用同一套备份）；
- 回退旧版本：文件里已经没有 `name`，旧代码会退回用 id 当名字——**这是回退的代价**，
  可接受（旧版本本来也不认识 `label`）。

### 4.4 用户感知

- 升级后**名字不变**（小栖还是小栖，因为读的是当前人格的 `name`）；
- 人格页顶部多一个「名字」输入框 + 说明：「改这里只影响她怎么称呼自己；
  人格文件里的名字已改成 label，只当标签用。」
- 切换人格时名字不变——**最明显的行为变化**，发版说明必须写。

## 五、面板与接口

### 5.1 人格页

- 顶部：`名字 [大肥鱼]`（全局，走 `POST /config`）；
- 列表每行：`label`（没有就 id）+ 标签 + 字数；不再把文件 `name` 当身份；
- 「用这个」只切 `persona.current` / `byChat`。

### 5.2 接口

- `GET /personas`：条目返回 `{ id, label, tags, chars, ... }`；**保留 `name` = label**，旧客户端不立刻坏；
- 顶层加 `globalName`；
- `POST /personas/read`：`{ id, label, name: label, raw }`。

### 5.3 市场

- 索引 schema 3 用 `label`，`name` 作兼容别名；
- 安装/预览/列表都显示 label；
- 市场人格不需要写名字，装了也不改全局名字。

## 六、边界与取舍

| 场景 | 行为 |
|---|---|
| `byChat` 指定人格 | 只换风格，名字不变（QQ-agent 同款） |
| `<<persona:>>` 运行时切换 | 只换风格，名字不变 |
| 人格正文自称 | 写作规范禁止；老文件里出现的，以全局名为准 |
| 多人格性别/自称不同 | 全局名会抹平差异，这是取舍 |
| 用户想"换人格换名字" | 改全局名（一次），或另起一个机器人实例 |
| 回退旧版本 | 已清掉 `name` 的文件回退后会用 id 当名字（迁移的代价）；改过没被清的文件不受影响 |

## 七、分期

| 期 | 内容 | 验收 |
|---|---|---|
| **N0** | 读路径：905/908 用全局名；`label` 解析（`name` 别名）；`migratePersonaName`（读一次 + 清字段）；面板名字输入；`DEFAULTS.persona.name='大肥鱼'` | 老用户升级后名字不变；未改过的文件改完后状态仍是「已是最新」；改过的文件不动；换人格名字不变 |
| **N1** | `/personas` 返回 `label` + `globalName`；面板列表/市场列表改 label | 旧客户端仍显示（`name` 还在） |
| **N2** | 索引 schema 3 用 `label`；构建脚本校验；内置 8 份清理（label + 删自称）；市场写作规范 | 新人格不带名字，装完不影响全局名 |

**发布**：与 `MIN_VERSION` 一起进 0.11.0。

## 八、测试点

1. **迁移**：空名字 + 当前人格 `name: 小栖` → 配置写成「小栖」；该文件 `name` 改名为 `label`；市场人格状态仍 `same`（靠 localSha）；
2. **迁移幂等**：第二次启动不覆盖用户后来改的名字；
3. **默认值**：全新安装 → `大肥鱼`；
4. **回退链**：配置空 + 人格无 label → id；全空 → 大肥鱼；
5. **提示词**：905/908 用全局名，不用人格文件 `name`；
6. **换人格**：`byChat` 切到 snarky，名字仍是全局名；
7. **市场**：只有 `label` 显示 label；只有 `name` 显示 name；都没有显示 id；
8. **改过的不清**：手改过的人格迁移时保持原样（`name` 还在，但不进提示词）；
9. **回滚**：已清 `name` 的文件回退旧版本后用 id 当名字（记录该行为）。

## 九、风险

- **「换人格不换名字」是行为变化**，发版说明 + 人格页文案要提前讲；
- **清字段会改 sha**：必须按 §3.3 的矩阵处理（记 `localSha` / 跳过改过的），
  否则市场人格会集体变成「你改过」，从此收不到更新；
- 内置人格清理会改 sha，用户看到一次「有更新」，需在发版说明里说明；
- `config.persona.name` 语义升级，注释和迁移日志必须写明白，避免以后被当废弃字段删掉；
- 正文自称是最大的冲突源，靠写作规范 + 内置清理，不能靠提示词硬纠。
