### 1.3 bot 侧真 bug：预发布版本把插件全判不兼容

现象：`npm test` 崩在 `pm.loaded.get('brain').ctx`，插件全被拒。

根因：`satisfies('1.0.16-beta.1', '>=0.1.0')` 按 npm 的预发布语义返回 **false**——预发布版本默认不满足普通范围。

修法：`src/semver.js` 新增

```js
compatibilityVersion(v)  // '1.0.16-beta.1' → '1.0.16'
satisfiesFramework(v, range)  // 用基线版本比较
```

`plugin/loader.js` 三处兼容性检查改用 `satisfiesFramework()`，`satisfies()` 的 npm 语义**不动**。

### 1.4 宿主新能力 `POST /v1/send`（提交 `e281291`）

扩展此前只能「投递一句话跑一轮模型」，画完图 / 刷完 B 站都发不出去。

```
POST /v1/send        scope: message:write
{ scene, target, text?, files?, card?, requestId? }
→ 200 { ok, scene, target, text:{ok,id,message}|null, files:[{file,ok}], card:{ok,id,message}|null }
→ 400 参数/文件不合法（message 有具体原因）
→ 403 群没有 group_push 授权，或令牌没绑扩展却要发文件
```

- **官方图文卡片**是 `msg_type=8`（2026-10-28 新增，群聊/单聊都支持）。框架从 v1.0.7 就有 `msg.replyTuwen`，外接协议 `msg.send` 也透传 `card`，**缺的一直是 dsh-roost 的 `channel.send`**——现在补上了。
- 卡片 `{title, description, url, picUrl}` 四字段必填，`title ≤50` 字、`description ≤200` 字、`url`/`picUrl` 必须 https 且 ≤1024。校验在宿主侧做（`tuwenProblem()`），因为平台只回笼统的 `304061`。
- 卡片与 markdown **互斥**：一条消息只能一种富文本，有 card 就不发正文。
- `files` 只认扩展自己目录（`<dataDir>/extensions/<extId>/`），`resolve` + `realpath` 双检（挡 `../`、软链、`bili-evil` 这种前缀相同的兄弟目录）。单文件 20MB、一次 4 个、`.exe/.bat/.ps1` 等可执行后缀拒收。
- 发文件走 `outActions`，复用去重 / 冷却 / 账本 `requestId`。

#### 3.1.2 扩展的能力边界

宿主给扩展的 `/v1` 端点（scope 见 `docs/API.md`）：

| 端点 | 用途 |
|---|---|
| `POST /v1/send` | **发文本 / 文件 / 图文卡片**（主力） |
| `POST /v1/message` | 投递一句话进入站链路、跑一轮模型（不是发消息） |
| `POST /v1/say` | 让机器人主动说一句（仅文本） |
| `POST /v1/proactive` | 排一条主动消息（受清醒时段/频次约束） |
| `GET /v1/state` `mood` `context` `memory` | 只读 |
| `POST /v1/memory` `memory/ext.add` | 写记忆 |
| `session.*` / `agent.*` | 会话与独立 agent（扩展令牌一般拿不到 `agent:write`） |

**扩展怎么找到自己的目录**：宿主只给 `ROOST_API_URL` / `ROOST_EXT_ID` / `ROOST_LAUNCHER_DIR`，没有数据目录。用模块路径：

```js
import { fileURLToPath } from 'node:url';
const SELF_DIR = fileURLToPath(new URL('.', import.meta.url));  // <extensions>/<id>/
// 存图 → path.join(SELF_DIR, 'out', 'x.png')
// 发图 → files: ['out/x.png']（相对路径，宿主拼成 <dataDir>/extensions/<id>/out/x.png）
```

#### 3.1.3 三条硬约束

1. **声明式 UI 只读**（`src/ext-ui.js`，别的窗口的 6.1）：4 形态（`table/cards/list/log`）+ 7 字段（`text/number/url/time/tag/image/progress`），数据来自扩展目录内 JSON（≤256KB、≤200 行），宿主只读、不执行扩展代码。**没有按钮、没有表单、没有「现在刷一轮」。**
   - 推荐做法：动作做成 MCP 工具（`bili_run` / `image_test`），用户在 QQ 里说一句由模型调。零宿主改动，也符合「模型是操作者」——aurabot 那些按钮本质就是「替用户发一句指令」。
   - 备选：宿主补 `ui.actions`（声明按钮 → 面板点击 → 宿主代调扩展工具）。工作量中等，**建议单独开任务**，别和扩展开发混在一起。
2. **配置走 `plugin.json` 的 `config`**：宿主渲染表单、落盘、下发。非敏感 → env `ROOST_EXT_CONFIG`（JSON 字符串）；`secret: true` → env `ROOST_EXT_SECRET_<KEY>`。生图 API Key、B 站 Cookie 都用 `secret: true`，别自己造存储。类型只有 `string/number/boolean/select/array/object`，**没有 path/file**。
3. **扩展是独立进程**：定时刷可以自己 `setInterval`；「只在醒着时间刷」读 `GET /v1/state`。改完必须重启 DSH 才重拉子进程，热重载不会重拉。

## 5. 纪律与已知坑

### 5.1 纪律

- **只本地提交，不推送、不发版**（主人 2026-11-14 03:0x 明确要求）。`git commit` 即可，不 `push`、不 `npm publish`、不建 tag。
- 别 `git add -A`（见 §2.1）。
- 改完先跑 `npm test`，全绿再 commit；改过 `api-v1.js` / 插件清单要跑 `ext-docs` / `build-index`。

### 5.2 已知坑（都踩过）

| 坑 | 现象 | 原因 / 修法 |
|---|---|---|
| 预发布版本判不兼容 | 插件全被拒，`pm.loaded.get('brain')` 崩 | `satisfies('1.0.16-beta.1','>=0.1.0')` 返回 false。用 `satisfiesFramework()` |
| npm publish 后 registry 404 | 打印 `+ pkg@ver` 但查不到 | 新版包有处理队列，约 2 分钟。用 `curl registry.npmjs.org/<pkg>/<ver>` 轮询，**别换版本号重发** |
| 表情补标签「都补过了」 | 功能看起来没生效 | `tags` 会退回文件名拆词，判据要用「侧车文件是否存在」 |
| 补标签任务卡 0% | 前端等不到结果 | `createTagJob` 初始 `running` 必须为 `true`，否则前端在第一片跑完前就 break |
| 测试 rmSync EBUSY | Windows 上子进程刚 kill | 清理失败不该判测试红，用 try/catch 包住 |
| SSE 测试偶发红 | 全量并发时 `sseHits` 为 0 | `wsRetryCooldownMs: 60` 太紧，改 400ms |
| 17321 端口「为什么还开着」 | 以为移除 ai-chat 后该关掉 | 它是 dsh-roost 自己的固定回环服务（`server.port`），承载 `/v1`、`/tts`、`/health`。DSH 面板端口是随机的，扩展需要固定地址。**别关** |
| 图文卡片 `picUrl` | 本地截图塞进卡片发不出 | 必须 https。本地图走 `files`，不要塞 `card` |
