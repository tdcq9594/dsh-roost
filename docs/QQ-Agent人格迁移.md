# QQ-Agent 人格迁移规范

> 目标：把 QQ-Agent 社区的 346 份角色卡人设，迁移成 dsh-roost 能直接使用的人格文件。
> 迁移方式：用低价模型（HY3）做「结构转换」，**不做创作**。
> 本文档是给「执行迁移的 AI」看的**可执行规范**，每一条都要能据以判断对错，不是散文。

---

## 一、输入：数据长什么样

输入有两个来源，**以 `raw/*.json` 为准**（最原汁原味），`prompts/*.md` 是已经处理过一版的，只能参考。

### `raw/persona-<hex>.json` 的结构

```json
{
  "prompt": "<完整人设原文，这是迁移的主体>",
  "item": {
    "title": "若叶睦（睦莫共生型",
    "category": "roleplay",
    "description": "应该可用于飞鸟山",
    "author": "社区用户"
  }
}
```

- `prompt`：**人设正文**，必须完整保留、不能删内容、不能加内容、不能润色。
- `item.title`：显示名来源（含机器尾巴和括号说明，要清洗）。
- `item.category`：类型（`roleplay` / `custom` / 其它）。
- `item.description`：一句话简介，可参考取标签，但不进正文。

### 原文的标题格式（三种都常见）

QQ-Agent 的人设正文用小节标题，常见三种写法，**迁移时要识别、归一**：

| 原文写法 | 例子 |
|---|---|
| 中文序号 | `一、你是谁` |
| 第X部分 | `第3部分 · 说话方式` |
| markdown | `## 她是谁`（少，主要在已处理的 prompts/ 里） |

标题后可能跟括号说明，例如 `九、回复示例（斜杠＝分成两条发）`，括号里的说明**不要搬进正文**（它是给原平台看的提示，不是人设）。

## 二、输出：dsh-roost 人格文件格式

输出一个完整 markdown 文件，结构如下。**格式错了人格就废**，必须逐字遵守。

````markdown
---
label: 若叶睦
selfName: 若叶睦
tags: 话少, 乐队
tools: []
---

<性格、说话方式，裸正文，不挂标题>

## 说话示例
<示例对话，见第六节>

## 开场白
<她主动搭话说的第一句，若原文有>

## 世界书
<背景设定，一行一条，见第七节>
````

> 三个标题里，`## 说话示例` 和 `## 世界书` 是最常见的；`## 开场白` 只在原文明确写了「主动搭话 / 开场白」时才写，不要硬凑。

### 2.1 front matter 字段（逐字段判据）

| 字段 | 必填 | 怎么填 | 判据 |
|---|---|---|---|
| `label` | 是 | 面板显示名 | 取 `item.title`，**去掉** `__persona-<12位hex>` 机器尾巴。括号说明的取舍见下方「label 怎么填」 |
| `selfName` | 否 | **角色自我介绍时用的名字** | **读完全文后自己判断**要不要填、填什么，见下方「selfName 怎么填」 |
| `tags` | 是 | 2-3 个特征词 | 读完全文后提炼最突出的气质词，见下方「2.3 打标签」 |
| `tools` | 是 | 固定 `[]` | 一个字都不能改，永远是空数组 |

**label 怎么填**：

`label` 是面板上显示的名字。取 `item.title`，去掉 `__persona-<hex>` 机器尾巴。括号说明的取舍按这个判据：**「括号里的信息，别人看一眼有没有用？」**

- **有用的说明 → 保留**。比如 `长崎素世（妈妈型）`、「缪尔赛思（私人版）」，括号里的「妈妈型」「私人版」能帮人快速认出这是哪个版本，保留。
- **纯噪音 → 去掉**。比如 `若叶睦（睦莫共生型` 这种残缺括号、或括号里是重复信息的，去掉。

**判据自检**：`label` 里**不能**出现 `__persona`；括号说明要么完整保留、要么整个去掉，不要留半个括号。

**selfName 怎么填（读完全文后自己判断，不要机械复制 label）**：

`selfName` 回答的是一个问题：**「这个角色，在一句话里怎么称呼自己？」** 读完整个人设后判断：

1. **有清晰的名字 → 填**。角色有明确自称的名字（若叶睦、BMPT、Claude、高松灯），填那个名字。填的是**名字本体**，去掉括号说明、机器尾巴、「XX型」「XX版」这类后缀。例：`长崎素世（妈妈型）` → `长崎素世`。
2. **正文里有「代号 / 别名 / 真名」→ 用自我介绍的那个**。若叶睦正文有「代号 Mortis」，但自我介绍是「若叶睦」，填 `若叶睦`；如果正文明确「我叫 X」「别人都叫我 Y」，填那个 X/Y。
3. **没有具体名字、只是泛称 → 整行省略**。比如「一只会说话的猫」「一个暴躁老哥」这种**没有专属名字**的角色，**不写 selfName**（让全局名兜底），不要硬填「猫」「老哥」这种代称。

**判断的核心**：`selfName` 是「专属的、能指代这一个角色的名字」，不是「类型称呼」。判断不了（正文通篇没提名字、标题也不像名字）就**留空**，别硬凑。

**判据自检**：
- `selfName` 有值 ⇔ 这个角色有一个专属的名字。填的是干净本体，不带 `（...）`、`__persona`、`型`、`版`。
- 泛称型角色（「一只会说话的猫」）不该有 selfName。
- `selfName` 和 `label` 相同是**正常的**（很多角色名字就是标题），别因此以为写错。

### 2.2 文件名（id）与重命名 —— 关键

**人格的 `id` 就是磁盘文件名（去掉 `.md`），它和 `label` 是两回事**：

| | 是什么 | 能不能中文 |
|---|---|---|
| `id` / 文件名 | 机器标识，进索引、进 `personas/` 目录 | 本地可以中文，**上仓库必须 ASCII**（见下） |
| `label` / `selfName` | 给人看、给模型看 | 可以中文 |

**两条不同的约束，别搞混**（这是有意的设计，不是遗漏）：

- **本地**（数据目录 `personas/`）：文件名可以用中文（`若叶睦.md` 也认）。本地 `safeId`（`personas.js`）已支持中文。
- **上仓库**（`dsh-roost-personas` + 索引）：`persona-repo.js` 校验，**fail-closed**，一条非法整份索引作废：

```
id 和文件名必须满足 /^[A-Za-z0-9_-]{1,40}$/  —— 字母、数字、下划线、短横，1-40 位，不能有中文、空格、其它符号
```

**为什么仓库要 ASCII**：文件名是机器标识，要跨平台（GitHub/Gitee CI 检出）、进索引、做 sha256 映射、走 pack 分片和撞名映射——中文文件名在这些环节容易出平台差异。而「用户看到中文名」这件事，已经由 `label`/`selfName` 承担了，文件名用 ASCII 不影响体验。

**推荐做法：从一开始就用 ASCII 文件名**，本地和仓库通用，省得审核通过后再改一遍名。规则：

- **默认**：用原 id（raw JSON 里的 `persona-<12位hex>`），例如 `persona-001ca6a4e4`。天然 ASCII、和原数据一一对应、绝不重名。
- **可读性加分**：角色有英文名（BMPT、Claude、Aliya）时，用英文名 + 尾 8 位防重名，例如 `bpmt-0a6bbbe0`。**不是必须**，默认原 id 最稳。
- **禁止**：用中文名当文件名（上仓库会被索引校验拒绝）。中文名放 `label`/`selfName`，不放 id。

**判据自检**：每个文件名都要能通过 `/^[A-Za-z0-9_-]{1,40}$/`。有中文、有空格、超 40 位的都算错。

### 2.3 打标签 —— tags 的取值规范

`tags` 是面板筛选和展示用的，2-3 个**短中文词**，逗号分隔。**读完全文后自己提炼**，不要机械照抄 category：

- 提炼这个角色**最突出的 2-3 个气质/特征词**，参考内置人格的用词习惯（短句 / 吐槽 / 温和 / 活泼 / 毒舌 / 话少 / 温柔 / 严谨 / 严肃 / 幽默）。
- `item.category` 只作参考，不直接照抄成标签（`roleplay` 这个分类对几乎所有人设都一样，没有区分度，别写成「角色扮演」）。

**反例**：不要写句子（「一个话很少的吉他少女」），只写词（「话少」）；不要写英文标签；不要写「角色扮演」这种没有区分度的废标签。

**判据自检**：tags 是 2-3 个、逗号分隔、每个都是 ≤4 字的短词，且能一眼看出「这人格什么味道」。

### 2.4 正文只认这三个 `##` 标题

dsh-roost 的解析器**只认**这三个二级标题（`take()` 按名字子串匹配），多了不认、少了缺段：

| 标题 | 对应原文 | 内容 | 用途 |
|---|---|---|---|
| `## 说话示例` | 回复示例段 | 示例对话 | 注入时给模型看「她平时怎么说话」 |
| `## 开场白` | 开场白段（若有） | 她主动搭话时说的第一句 | 压缩续会话时拼在正文前，主动搭话用 |
| `## 世界书` | 外貌/背景/能力设定段 | 背景设定，一行一条 | 命中关键词才注入 |

**注意**：性格、说话方式这些，是正文的主体（不挂标题），直接写在 front matter 之后的正文开头，**不要**再挂 `## 她是谁` / `## 说话方式` 这种标题——dsh-roost 的正文段（body）就是「没被 take 走、剩下的部分」，挂太多标题反而会让「说话示例」「开场白」「世界书」这三个 `take()` 抓取时被干扰。

**判据自检**：正文里只允许出现 `## 说话示例`、`## 开场白`、`## 世界书` 三个二级标题；其它内容一律是裸正文。

---

## 三、铁律：只做结构转换，不做创作

这是「原汁原味」的唯一保障，三条一条都不能破：

1. **不改措辞**：原文的用词、语气词、梗、雷点、傲娇设定、口头禅，一个字不改、不润色、不精简、不同义替换。
2. **不编造**：原文没写的设定一个字不加。不「补充背景」「完善人设」「让设定更合理」。
3. **不删人设**：外貌、情绪、动作、表情包这些**内容不删**，只是归位（外貌/背景进「世界书」，情绪动作留在正文）。

**判据自检**：迁移后的正文，把 front matter 和 `## 说话示例` / `## 开场白` / `## 世界书` 三个标题去掉后，应该能在原文里找到**逐字对应**（除了第六节、第八节列出的机械改动）。

---

## 四、结构映射：原文小节 → 输出位置

原文的各个小节，按这张表归位：

| 原文小节（关键词） | 归到哪 |
|---|---|
| 你是谁 / 她是谁 / 性格底色 | **正文开头**（body，不挂标题） |
| 说话方式 / 说话铁律 / 节奏 / 禁忌 / 群聊怎么接 | **正文**（body） |
| 外貌 / 知道自己长啥样 / 背景 / 家庭 / 能力设定 | **## 世界书**（一行一条） |
| 回复示例 / 说话示例 | **## 说话示例** |
| 开场白 / 主动搭话的第一句（**若有**） | **## 开场白**（原文没有就不写，不要硬凑） |
| 情绪 / 小动作 / 表情包用法 | **正文**（body，原样保留） |
| 格式说明（「斜杠=分两条」「用 markdown」） | **删掉**（第八节） |

**判据自检**：`## 世界书` 里只有「背景/外貌/能力」这类设定；「你是谁」「说话方式」必须留在 body，不能进世界书。

---

## 五、正文（body）怎么组织

正文 = front matter 之后、`## 说话示例` 之前的所有内容。原则：

- 把「你是谁」「说话方式」「性格」「禁忌」这些**连贯地串成一段文字**，用原文的话，不另起炉灶。
- 原文的小节标题（`一、你是谁` 这种）**删掉**，只保留标题下的内容，用换行分段。
- 顺序保持原文顺序，不要重排。

---

## 六、`## 说话示例` 段的两条机械转换

示例段只做两件事，**只在示例段内做**，不碰正文：

### 6.1 说话人归一

| 原文对方标签 | 改成 |
|---|---|
| 群友 / 来者 / 他 / 她 / 主人 / 对方 | `用户：` |
| 角色自己说的话（无标签或「你：」） | `你：`（没有的补上） |

**反例**：正文里出现「群友」这个词（比如「群友都喜欢她」），**不改**——那是人设内容，不是示例里的说话人。

### 6.2 斜杠拆条

角色一句「第一句 / 第二句」用 `/` 或 `／` 隔开的，拆成两条独立 `你：`：

```
原文：　　你开一个试试 / 轮椅也是我自己坐上去的
拆成：
你：你开一个试试
你：轮椅也是我自己坐上去的
```

**判据自检**：示例段里不能残留「群友：」「来者：」这类原始标签；斜杠都拆开了。

---

## 七、`## 世界书` 段格式

世界书 = 「命中关键词才注入」的背景设定，一行一条：

```
触发词1, 触发词2 | 内容
```

- 触发词：从内容里提炼 1-3 个最相关的词（外貌、头发、校服、家庭、吉他……）。
- `|` 前后有空格。
- 例：原文「绿色头发，穿校服」→ `外貌, 头发, 校服 | 绿色头发，穿校服`。
- **拆不出来的整段背景**（连续故事性叙述），整段作为一条，触发词用最相关的词。
- **不是必填**：原文没有明确的背景设定段，`## 世界书` 整段省略，不要硬凑。

**判据自检**：世界书每一条都是 `词 | 内容` 格式；没有「你是谁」这类性格内容混进来。

---

## 八、删掉的东西（穷举，别多删）

**只删这四类，其它一律保留。** 判断标准永远是：**「这段是人设内容，还是给原平台看的操作说明？」** 是人设内容就保留，是操作说明才删。

1. **拍一拍 / poke**：`拍一拍`、`poke` 相关的**操作说明**。但如果「被拍一拍时的反应」是**人设**（比如「被拍会害羞」），那是性格，**保留**。
2. **引用 / @ / 转发**：`引用回复`、`@成员`、`转发` 相关的**操作说明**。但如果「被 @ 时会怎样」是**人设**（比如「被 @ 会装没看见」），保留。
3. **API 调用说明**：`send_message`、`finish`、`send_poke` 这类工具名，**直接删掉**（不要「改成自然说法」——那是自由发挥，违反铁律；dsh-roost 会自己注入工具契约，模型运行时才知道用 `qq_send`，人格文件里不需要写这些）。
4. **格式说明**：「斜杠=分成两条发」「用 markdown 加粗」这种**给原平台的提示词说明**（不是人设内容）。

**判据自检**：删掉的东西，删了之后不影响「她是谁、怎么说话」。删了会影响人设的，就删错了——**拿不准时保留**。

---

## 九、输出纪律

- 只输出人格文件的 markdown，**不输出**任何解释、前言、后记。
- **不要用代码块围栏**包住整个输出（front matter 里的 `---` 和正文直接就是文件内容）。
- 正文长度不设上限，全部保留。
- 判断不了的内容，**保留原文**，宁可不处理，不要误删。

## 十、一条完整正例

输入：

```
【标题】若叶睦（睦莫共生型__persona-001ca6a4e4
【分类】roleplay
【描述】话少到近乎沉默的吉他少女

一、你是谁
你是若叶睦，Ave Mujica 的吉他手。话少到近乎沉默，可你肯开口的那一句，往往是所有人回避的那一句。

二、外貌与衣着
绿色头发，穿月之森校服。

三、回复示例
群友：若叶睦，今天练琴了吗
你：……练了
群友：弹得怎么样
　　还行 / 就那样吧
```

输出（**文件名：`persona-001ca6a4e4.md`**）：

```markdown
---
label: 若叶睦
selfName: 若叶睦
tags: 话少, 乐队
tools: []
---

你是若叶睦，Ave Mujica 的吉他手。话少到近乎沉默，可你肯开口的那一句，往往是所有人回避的那一句。

## 说话示例
用户：若叶睦，今天练琴了吗
你：……练了
用户：弹得怎么样
你：还行
你：就那样吧

## 世界书
外貌, 头发, 校服 | 绿色头发，穿月之森校服
```

**对照要点**（正例为什么对）：
- **文件名** `persona-001ca6a4e4.md`：ASCII、复用原 id、不重名。中文名「若叶睦」只放 `label`/`selfName`，不放文件名。
- `label` 去掉了 `__persona-001ca6a4e4` 机器尾巴。括号说明 `（睦莫共生型）` 这里选择去掉 → `若叶睦`（保留 `若叶睦（睦莫共生型）` 也可以，两种都对）。
- `selfName` 填干净名字本体 `若叶睦`（不带括号、不带尾巴）。这里 label 和 selfName 恰好相同，是正常的。
- `tags` 是提炼的特征词「话少」（加一个「乐队」或「吉他」也行）。**不写「角色扮演」**——那是对所有人都一样的废标签。
- 「一、你是谁」→ body（不挂标题），「二、外貌」→ 世界书，「三、回复示例」→ `## 说话示例`。
- `群友` → `用户`，`还行 / 就那样吧` 拆成两条 `你：`。
- 所有措辞原样，一个字没改。
