# 自驱引擎（实验，默认关）

> 2026-11-14 落地。代码：`src/autotelic.js`（引擎）+ `src/autotelic-ledger.js`（哈希链账本）。
> 面板：「主动搭话 → 07 自驱引擎（实验）」。配置段：`config.autotelic`。

## 0. 一句话

给她**一间自己的屋子**（独立会话）、**一本别人代记的账**（哈希链账本）、
**一件自己想做的事**（立项），以及**一道动手前的闸**（频率 / 时段 / 是否允许动手 / 连续失败自动卡住）。

## 1. 为什么默认全关

这是本项目里唯一「没人叫她、她自己决定要做事」的模块。和「授权分级」铁律的冲突点很具体：
**无人值守时的工具调用，出了事没有人在场喊停**。

所以四个开关全是关的，缺一个她都不会动：

| 开关 | 默认 | 关着时的行为 |
|---|---|---|
| `enabled` | `false` | 一行代码都不跑，`think` / `step` 直接拒并记一条 `deny` |
| `allowAct` | `false` | 只能想，prompt 里明确禁止调工具 |
| `heartbeatMin` | `0` | 不自动心跳，只能从面板手动点 |
| `seeds` | `[]` | 没东西可琢磨，立项直接拒 |

另外两条硬边界：

- **绝不往主人私聊推**。产物只进账本与面板；「主动发消息」仍归「主动搭话」那条有人工开关的路。
- **失败要进账本**。只记成功的话账本会看起来一帆风顺，那是假账。

## 2. 与 aurabot `AUTOTELIC-PLAN v3` 的关系

借**形态**，不借**实现**。

| 那份方案 | 我们 |
|---|---|
| 跑在 Cordis 上（`hub.js:433` 改 `presetId`、`cordis.patch.yml` 加 preset） | DSH 插件，会话走 `ctx.agents.create()`（复用 `src/agent-v1.js`） |
| 工具收放靠 preset + `tools/pre-execute` 钩子 | 靠 `allowAct` 决定 prompt 措辞；真正的工具沙箱**没做**（见 §6） |
| 五期 P0–P4（到「会写代码 / 跑 Python」） | 只做到 P1（会想），P2 的「动手」留了开关但没实现执行层 |
| 好奇分门槛 + 每日一页复盘 + 做梦窗口 | 好奇分（`scoreCuriosity`）+ 每日复盘（`review`，纯统计不调模型）；**不做做梦窗口** |

**刻意不做**两件：

- **不做「她自己改频率」的自动调参**。`tune` 这个 kind 在账本里留着，但没有任何代码会自己调——
  一个会自己放宽自己上限的引擎，等于没有上限。
- **不做「自己写代码 / 跑 Python」**。那两件要单独设计沙箱，不该顺手带进来。

## 3. 账本（这是整个设计的地基）

文件：`<数据目录>/autotelic-ledger.jsonl`，一行一条，**只追加**。

```
{"seq":1,"at":...,"kind":"project","note":"自动立项","payload":{...},"prev":"000...0","hash":"092b..."}
```

- `hash = sha256(prev + 稳定序列化的正文)`，`prev` 掺进哈希是链的关键：
  只哈希正文的话，删掉中间一条、后面各自重算就都合法了。
- **稳定序列化**（键按字典序递归排）是必须的：`JSON.stringify` 的键序跟着对象构造顺序走，
  同一份数据换个构造方式就得到不同哈希，链会假断。
- 校验返回**断在第几条 + 原因**，不是布尔：「账本坏了」用户没法处理，「第 37 条对不上」才能去查那一轮。
- 写之前先验全链：链坏了就拒绝追加，不造一条永远验不过的记录。
  （第一版只验最后一条，而 `verifyChain` 是按「第一条 seq 必须为 1」验的，
  于是**第二条之后的追加全被拒**，账本只写进两条——这个 bug 有回归测试钉住。）

`kind` 是闭集：`boot` / `project` / `step` / `deny` / `stuck` / `review` / `tune` / `manual`。

## 4. 闸门顺序（顺序本身是语义）

```
总开关 → 卡住 → 安静时段 → 今日额度 → 有没有种子
```

每一步拒绝都**带具体原因**并记一条 `deny`。「没反应」是最难查的状态。

- `maxPerDay` 默认 2：立项不算次数，**推进才算**。
- `failLimit` 默认 2：连续失败 2 次 → 记 `stuck` + 卡住 `stuckHours`（默认 12 小时）。
  成功一次清零。
- `quietStartHour == quietEndHour` = 不设时段；跨零点（22→7）按 `h >= a || h < b` 判。

## 5. 好奇分

```
score = 0.55 × 新鲜度 + 0.45 × 搁置度 − 疲劳
新鲜度 = 1 − e^(−ageDays/7)      （7 天内快速上升后饱和）
搁置度 = min(1, deferred/3)
疲劳   = min(0.6, doneCount × 0.2)
```

只用来**排序**，不写进任何结论性描述——0.73 分的项目不比 0.68 分「更值得做」，只是先看它。
推进满 3 次的种子会被拒（理由是「先放着」），不是永远不能做，是这一轮轮不到。

## 6. 已知限制（都还没做）

1. **没有真正的工具沙箱**。`allowAct: true` 只是改了 prompt 措辞，没有在工具层收走危险工具。
   要做必须单独设计（参考扩展机制那套 `resolvePolicy` 的 deny-first）。
2. **没有候选自动发现**。种子要手填，不会从日记/记忆里自己找「未完成的事」。
3. **没有做梦窗口**（那份方案的 `10.1`），也没有「心跳感」看护面板（`10.2`）。
4. **复盘不调模型**，是纯统计。要「她自己写一页总结」得再设计（那会花一次模型调用）。

## 7. 验收

`test/autotelic.test.js` 21 条 + `test/routes.test.js` 4 条，覆盖：

- 链能验过、改一条断在自己、删中间一条断在后面、尾部坏了拒写、坏行跳过
- `kind` 闭集、`note` 长度上限、按天统计（手动立项也算立项）
- 配置夹紧、安静时段跨零点、好奇分单调性
- 默认关时一律拒绝**且拒绝要进账本**、没种子给具体理由
- 立项不跑模型、状态跨重启、推进成功/失败、失败到上限卡住、卡住期间不再跑
- `heartbeatMin = 0` 时 tick 什么都不做、没接 `run` 给明确原因、复盘、预览不记账
